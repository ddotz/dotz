# JANDI 연결 (온보딩)

설정 → JANDI 화면의 **연결**을 누르면 dotz가 사내 JANDI 연결을 준비합니다. 웹훅 URL과 토큰을 먼저 붙여 넣을 필요가 없습니다. 이미 있는 `~/.dotz/messengers/jandi.json`과 저장된 세션을 먼저 재사용합니다.

## 온보딩이 하는 일

1. `~/.dotz/messengers/jandi.json`의 방(room), 발신 토큰, 수신 웹훅 URL을 확인합니다. 방마다 두 웹훅이 갖춰져 있으면 바로 켜고 연결을 확인합니다.
2. 설정이 비어 있으면 오너의 Aside 브라우저(백그라운드)에서 JANDI 관리자 화면을 열어 토픽과 Incoming/Outgoing Webhook을 만들고, 발급된 URL과 토큰을 읽어 설정 파일에 0600으로 저장합니다.
3. 방 이름은 웹앱 구조를 그대로 따릅니다: 메인 대화, 프로젝트, 알림, 작업 기록. 이미 있는 방과 키는 건드리지 않습니다.
4. dotz가 여는 수신 포트(`listen.port`, 기본 8787)와 LAN 주소를 확인하고, JANDI 서버가 이 컴퓨터에 닿는지 검사합니다.
5. 연결되면 방 목록과 마지막 수신·발신 시각을 화면에 보여 줍니다.

## 오너가 하는 일

- JANDI 관리자 로그인과 2단계 인증
- JANDI가 요구하는 확인 화면(관리자 권한 안내, 캡차 등)

화면에 한 단계로 표시됩니다. 끝나면 dotz가 이어서 진행합니다.

## 저장되는 것

| 무엇 | 어디 | 권한 |
| --- | --- | --- |
| 방 목록, 발신 토큰, 수신 웹훅 URL | `~/.dotz/messengers/jandi.json` | 0600 |
| 온보딩 진행 상태(비밀 없음) | `~/.dotz/onboarding/jandi.json` | 0600 |
| JANDI 세션(선택, "나와의 대화" 읽기) | `~/.dotz/secrets/jandi-session` (dotz_auth 암호화) | 0600 |

## 복구와 연결 끊기

- **직접 입력**을 열면 받는 주소·포트, 기본 수신 웹훅 URL, 방별 웹훅 URL과 토큰을 직접 넣을 수 있습니다. JANDI가 웹훅을 API로 만들지 못하는 경우의 복구 경로입니다.
- 허용 목록(말을 걸 수 있는 사람)은 같은 화면에서 관리합니다.
- **연결 끊기**는 이 컴퓨터에서 JANDI 설정을 지웁니다. JANDI 쪽 웹훅은 JANDI 관리자 화면에서 직접 지웁니다.
- 온보딩이 실패하면 이유 한 줄과 다음 할 일 한 단계가 표시됩니다. **연결**을 다시 누르면 저장된 것부터 이어서 합니다.

## 한계

- JANDI는 웹훅을 API로 만들 수 없습니다. 관리자 화면 자동화가 실패하면 **직접 입력**으로 URL과 토큰을 넣어야 합니다.
- JANDI는 올린 글을 고칠 수 없어서 진행 상황 갱신을 하지 않습니다. 완료·실패·질문 같은 최종 글만 올라갑니다.
- 수신 포트는 사내망에서 열려 있어야 합니다. 포트를 인터넷에 공개하지 않습니다.
- 팀 관리자가 아니면 Team Outgoing Webhook을 만들 수 없습니다. 이때는 "나와의 대화" 읽기(`self_chat`)를 쓰며, 기존 문서 `docs/messengers/jandi.ko.md`의 7절을 따릅니다.
- Tailscale은 필요하지 않습니다. JANDI 연결은 웹 접속 방식과 별개입니다.
