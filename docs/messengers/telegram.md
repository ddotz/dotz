# Telegram 연결 (온보딩)

설정 → Telegram 화면의 **연결**을 누르면 dotz가 봇을 만들고 대화방을 찾습니다. 토큰을 먼저 붙여 넣을 필요가 없습니다. 이미 있는 설정과 `~/.dotz/secrets/telegram-bot-token`을 먼저 재사용합니다.

## 온보딩이 하는 일

1. 저장된 봇 토큰과 `~/.dotz/messengers/telegram.json`을 확인합니다. 토큰이 있으면 `getMe`로 바로 검증합니다.
2. 토큰이 없으면 오너의 Aside 브라우저(백그라운드)에서 Telegram Web을 열고 BotFather에게 `/newbot`을 보내 봇을 만듭니다. 발급된 토큰을 읽어 `secrets/`에 0600으로 저장합니다.
3. 오너가 봇과의 대화에서 **시작**을 누르면 `getUpdates`로 대화 ID를 읽습니다. 그룹을 쓰려면 봇을 그룹에 추가한 뒤 같은 방식으로 찾습니다.
4. 대화를 웹앱 구조에 맞춰 매핑합니다: 메인 대화, 알림, 작업 기록. 프로젝트 대화는 이름이 맞는 것을 찾고, 없으면 메인으로 보냅니다.
5. 봇을 켜고 `getUpdates` 폴링으로 오너 메시지를 받습니다. 답과 알림은 `sendMessage`로 보냅니다.

## 오너가 하는 일

- Telegram 로그인과 2단계 인증
- BotFather 대화에서 봇 이름과 사용자 이름 정하기(자동으로 제안된 값을 쓰면 그대로 진행)
- 봇과의 대화에서 **시작** 누르기
- 그룹을 쓰는 경우 봇을 그룹에 추가

화면에 한 단계로 표시됩니다. 끝나면 dotz가 이어서 진행합니다.

## 저장되는 것

| 무엇 | 어디 | 권한 |
| --- | --- | --- |
| 봇 토큰, 대화 매핑, 허용 사용자, 읽은 위치 | `~/.dotz/messengers/telegram.json` | 0600 |
| 온보딩 진행 상태(비밀 없음) | `~/.dotz/onboarding/telegram.json` | 0600 |

## 복구와 연결 끊기

- **직접 입력**을 열면 봇 토큰과 대화 ID를 직접 넣을 수 있습니다. BotFather 화면이 바뀌어 자동화가 실패했을 때의 복구 경로입니다.
- **연결 확인**은 `getMe`로 봇 이름과 사용자 이름을 확인합니다.
- **연결 끊기**는 `~/.dotz/messengers/telegram.json`을 지웁니다. Telegram 쪽 봇은 BotFather에서 `/deletebot`으로 지웁니다.
- 온보딩이 실패하면 이유 한 줄과 다음 할 일 한 단계가 표시됩니다. **연결**을 다시 누르면 저장된 것부터 이어서 합니다.

## 한계

- Telegram은 공개 웹훅 없이 `getUpdates` 폴링으로 받습니다. 메시지가 오면 최대 몇 초 늦게 처리될 수 있습니다.
- 봇은 먼저 말을 걸 수 없습니다. 오너가 **시작**을 눌러야 대화 ID를 알 수 있습니다.
- 허용 목록에 있는 사용자의 글만 명령으로 처리합니다. 그룹에서는 봇이 모든 글을 볼 수 있으므로 허용 목록이 중요합니다.
- 한 봇만 연결합니다. 여러 봇이 필요하면 설정 파일을 나누는 별도 작업이 필요합니다.
- 회사나 학교 네트워크가 Telegram API를 막으면 연결되지 않습니다. 이때는 웹앱만 씁니다.
