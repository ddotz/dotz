# JANDI 연결 (관리자용)

dotz는 사내 JANDI 서버와 사내망(LAN)에서 바로 연결됩니다. Tailscale은 필요하지 않습니다.
dotz가 직접 포트를 하나 열고, JANDI의 Outgoing Webhook이 그 주소로 메시지를 보냅니다. dotz의 답은 Incoming Webhook으로 JANDI에 올라갑니다.

## 1. 토픽 만들기

JANDI에서 다음 토픽을 만듭니다.

- 메인 대화: dotz와 일상 대화를 나누는 토픽입니다.
- 프로젝트 토픽: 프로젝트마다 하나씩 만듭니다. 토픽 하나가 dotz 프로젝트 채널(`ch:<채널 ID>`) 하나와 연결됩니다.
- 알림: 경고와 선택 질문(`[ask]`)이 올라오는 토픽입니다.
- 작업 기록(선택): 작업 기록을 따로 모아 보고 싶을 때만 만듭니다.

## 2. 토픽마다 웹훅 두 개 만들기

각 토픽에서 `커넥트(Connect)`를 열고 아래 두 가지를 추가합니다.

1. **Incoming Webhook**: 만든 뒤 나오는 웹훅 URL을 복사합니다. dotz가 이 주소로 글을 올립니다. 같은 화면에서 이름을 봇 이름으로, 프로필 이미지를 봇 이미지로 바꿉니다. 그렇지 않으면 답이 `Webhook 수신 (Incoming Webhook)` 이름으로 보입니다. 웹훅 글에는 이름과 이미지를 넣는 항목이 없어 dotz가 대신할 수 없습니다([JANDI 안내](https://support.jandi.com/ko/articles/connect-incoming-webhook-21bc249f)).
2. **Team/Outgoing Webhook**: 설정은 다음과 같이 합니다.
   - 키워드: `/땅콩` 처럼 정합니다. 이 키워드로 시작하는 글만 dotz에 전달됩니다.
   - URL: `http://<dotz 컴퓨터의 LAN IP>:<포트>/jandi/<방 ID>`
   - 만든 뒤 나오는 토큰을 복사합니다.

방 ID는 설정 파일에서 정하는 영문, 숫자, `-`, `_` 이름입니다(예: `main`, `alert`, `proj-web`). 토픽마다 서로 달라야 합니다.
Outgoing Webhook 사용 방법은 JANDI 안내를 참고합니다: https://support.jandi.com/ko/articles/connect-team-outgoing-webhook-aea2650b

## 3. 설정 파일

`<DATA_DIR>/messengers/jandi.json` (권한 0600, 소유자만 읽기·쓰기)

```json
{
  "enabled": true,
  "listen": { "host": "0.0.0.0", "port": 8787 },
  "allow_emails": ["boss@company.com"],
  "allow_names": [],
  "rooms": [
    { "id": "main", "name": "메인 대화", "kind": "main", "outgoing_token": "<토큰>", "incoming_url": "<Incoming Webhook URL>" },
    { "id": "proj-web", "name": "웹 프로젝트", "kind": "project", "project": "ch:123456789", "outgoing_token": "<토큰>", "incoming_url": "<URL>" },
    { "id": "alert", "name": "알림", "kind": "alert", "outgoing_token": "<토큰>", "incoming_url": "<URL>" },
    { "id": "worklog", "name": "작업 기록", "kind": "worklog", "outgoing_token": "<토큰>", "incoming_url": "<URL>" }
  ]
}
```

- `kind`는 `main`, `project`, `alert`, `worklog` 중 하나입니다. `project`는 `project`에 연결할 채널(`ch:<ID>`)을 함께 적습니다.
- 토큰과 웹훅 URL은 비밀입니다. 로그나 화면 공유에 노출하지 않습니다.
- 파일을 고치면 방, 토큰, 허용 목록은 바로 적용됩니다. `listen`(주소·포트)과 `enabled`는 dotz를 다시 시작해야 바뀝니다.

## 4. 허용 목록

- `allow_emails`: dotz에 명령할 수 있는 사람의 이메일입니다. 여기에 없는 사람의 글은 거부됩니다(403).
- `allow_names`(선택): Outgoing Webhook이 이메일을 보내지 않는 경우에만 쓰는 이름 목록입니다. 이름은 이메일보다 약한 식별이므로 꼭 필요할 때만 켭니다.
- 토큰이 틀리면 허용 목록과 관계없이 거부됩니다(401).

## 5. 동작 방식과 한계

- 키워드를 뺀 본문만 dotz에 전달됩니다. 보낸 즉시 `받았어요`라는 짧은 확인이 오고, 실제 답은 Incoming Webhook으로 따로 올라옵니다.
- 알림 토픽에 올라온 선택 질문에는 `/땅콩 1` 처럼 번호로 답합니다. 선택지는 본문에 한 번만 나옵니다.
- 봇의 답만 올라옵니다. 상태 표시는 이모지가 되고, 맡김 알림·재시작·업데이트 같은 게이트웨이 기록과 진행 글은 웹에만 남습니다. 질문, 알림, 실패는 그대로 옵니다.
- JANDI는 올린 글을 고칠 수 없어서 진행 상황 갱신은 올리지 않습니다. 완료·실패·질문 같은 최종 글만 올라옵니다.
- 4000자를 넘는 글은 여러 개로 나뉘어 올라옵니다.

## 6. 방화벽

- dotz 컴퓨터는 `listen.port`로 들어오는 연결을 사내망에서 허용해야 합니다. 예: macOS 방화벽에서 dotz(bun)의 수신 허용.
- 사내망 안에서만 쓰는 구성입니다. 포트를 인터넷에 공개하지 않습니다. 사내망만 쓰려면 `listen.host`를 LAN IP로 고정합니다.
- JANDI 서버에서 dotz 컴퓨터의 LAN IP로 접근할 수 있어야 하고, dotz 컴퓨터에서는 JANDI Incoming Webhook 주소로 나가는 연결이 되어야 합니다.

## 7. 관리자가 아닐 때: JANDI에 로그인해서 "나와의 대화" 연결

팀 관리자가 아니면 Team Outgoing Webhook을 만들 수 없고, 개인 커넥트의 Outgoing Webhook은 "나와의 대화"에서 키워드 명령을 받지 못합니다("등록된 커맨드가 없습니다"). 이때는 JANDI에 로그인만 하면 됩니다. 토큰이나 웹훅 URL을 복사해 붙여 넣을 일이 없고, 설정 파일도 고치지 않습니다.

### 연결하는 순서

1. 봇이 JANDI를 연결할지 먼저 묻거나, 대화에서 "잔디 연결해 줘"처럼 말하면 연결이 시작됩니다. 일반 채팅으로 부탁해도, **설정 > 메신저 > JANDI**의 **로그인으로 연결**을 눌러도 같은 흐름입니다.
2. 안내 한 줄이 나옵니다. JANDI가 공개하지 않은 웹 로그인 세션을 쓰고, 읽는 곳은 나와의 대화뿐이라는 내용입니다. 괜찮으면 계속합니다.
3. 아직 JANDI에 로그인하지 않았다면 Aside 앱에 열린 JANDI 탭에서 로그인합니다. 이미 로그인돼 있으면 이 단계는 없습니다.
4. 팀이 여러 개면 쓸 팀을 고릅니다. 하나뿐이면 묻지 않습니다.
5. 끝입니다. dotz가 팀, 본인, JANDI 봇, 나와의 대화방을 찾아 맞는 방인지 확인한 뒤에만 저장합니다. 확인이 안 되면 아무것도 저장하지 않고 이유를 알려 줍니다.

### 만료되면, 컴퓨터가 더 있으면

- JANDI 세션이 끝나면 알림이 한 번 오고, 설정 화면에 **JANDI 다시 연결**이 나옵니다. **설정 > 메신저 > JANDI**에서 누르면 같은 흐름으로 다시 로그인합니다. 키워드, 말머리, 컴퓨터 목록은 그대로 남습니다.
- 컴퓨터를 하나 더 붙일 때는 그 컴퓨터에서 같은 흐름을 한 번 거칩니다. 키워드는 그 컴퓨터 봇 이름을 따라 정해지니 컴퓨터마다 다릅니다. 서로 이름을 알려 주는 컴퓨터 목록은 **설정 > JANDI**에서 넣습니다(8절).

### 동작 방식

- 읽는 방은 나와의 대화 하나뿐입니다. 본인이 쓴 글 중 `dotz <내용>` 또는 `/dotz <내용>`(키워드는 `keyword`)으로 시작하는 것만 메인 대화로 전달됩니다. 메모, 웹훅 글, 다른 사람 글, 다른 사람과의 대화는 읽지 않습니다.
- 본인이 보낸 이미지·파일은 내용 없이 보내거나 캡션이 키워드 명령이면 턴에 `[attachment]`로 들어갑니다(`<DATA_DIR>/uploads/<날짜>/jandi-<메시지 id>/`에 저장, 크기 제한은 웹 업로드와 같음). 받지 못한 파일은 주소 줄로 남습니다.
- 켤 때의 마지막 메시지부터 읽고, 읽은 위치를 `<DATA_DIR>/messengers/jandi-selfchat.json`에 남겨 다시 시작해도 같은 명령을 두 번 처리하지 않습니다.
- 답은 수신 웹훅이 있으면 그 웹훅으로, 없으면 본인 세션으로 나와의 대화에 올라옵니다. 세션으로 올리는 답은 항상 `reply_prefix`(기본 `[봇 이름]`)로 시작해서 명령으로 다시 읽히지 않습니다. 이 경우 알림도 같은 방에 올라오고, 작업내역은 웹에만 남습니다.
- 답의 `[file]` 파일은 글 다음에 나와의 대화로 올라갑니다(메인 방 답, 나와의 대화가 연결돼 있을 때, 웹 파일과 같은 허용 규칙과 크기 제한, 답 하나에 10개까지). 못 보낸 파일은 웹에서 볼 수 있다고 한 줄로 알려 줍니다.
- 한 계정의 나와의 대화를 컴퓨터 여러 대가 함께 쓰면 컴퓨터마다 `keyword`가 다르고, 그 컴퓨터의 답은 자기 `reply_prefix`로 시작해 서로 구분됩니다. 캡션 없는 파일은 이 방을 읽는 컴퓨터 모두에 들어가니, 한 대에만 보내려면 그 컴퓨터의 키워드를 캡션으로 적습니다.
- 세션은 dotz 비밀 `jandi-session`(`{"refresh_token": "..."}`, 암호화 저장)에서 읽습니다. 비밀번호는 저장하지 않습니다. 토큰이 바뀌면 새 값으로 다시 암호화해 저장합니다.

**주의**: JANDI가 공개하지 않은 웹 클라이언트 API를 씁니다. JANDI가 바뀌면 동작이 멈출 수 있고, 그때는 게이트웨이 로그에 `jandi self-chat:` 오류가 남고, 다시 시도하는 간격이 최대 5분까지 늘어납니다.

### 직접 입력 (참고)

로그인 흐름을 쓰지 않을 때만 설정 파일의 `self_chat`을 직접 채웁니다. 시작할 때 `room_id`가 본인(`member_id`)과 JANDI 봇(`bot_id`)의 1:1 대화방인지 확인하고, 아니면 아무 메시지도 읽지 않고 멈춥니다. 세션 비밀은 `jandi-session`에 따로 넣어야 합니다.

```json
"self_chat": { "enabled": true, "team_id": 123, "room_id": 456, "member_id": 789, "bot_id": 321, "keyword": "dotz", "reply_prefix": "", "interval_ms": 3000 }
```

## 8. 나와의 대화로만 닿는 컴퓨터를 컴퓨터 목록에 올리기

Tailscale에 없고 같은 "나와의 대화" 방을 다른 키워드로 읽는 컴퓨터는 웹 앱 **설정 > 메신저 > JANDI**의 **잔디로 닿는 컴퓨터**에서 넣습니다. 나와의 대화가 켜져 있으면 이 항목이 보입니다. 이름, 키워드, 답 머리말을 적고 **컴퓨터 추가**를 누르면 바로 적용되고, 게이트웨이를 다시 켤 필요는 없습니다. 그러면 웹 앱의 컴퓨터 목록에 Tailscale 컴퓨터와 나란히 올라오고, 이름 아래에 `잔디로 주고받아요`가 보입니다. 고르면 평소 쓰던 채팅 화면이 그대로 열리고, 제목이 그 컴퓨터 이름으로 바뀝니다. 그 컴퓨터를 고른 채로 홈, 프로젝트, 모니터링을 누르면 이 컴퓨터가 아니라 그 컴퓨터가 마지막으로 보낸 상태 요약을 읽기 전용으로 보여 줍니다(아래 **상태 요약**). 설정처럼 원격으로 볼 수 없는 화면에는 `잔디로 연결된 컴퓨터는 채팅으로 요청해요`와 채팅 열기 단추, 이 컴퓨터 설정으로 돌아가는 단추가 보입니다. 컴퓨터 목록에서 이 컴퓨터를 다시 고르면 모든 화면이 이 컴퓨터의 것으로 돌아옵니다.

같은 내용은 설정 파일의 `self_chat.peers`에 저장됩니다.

```json
"self_chat": { "enabled": true, "team_id": 123, "room_id": 456, "member_id": 789, "bot_id": 321, "keyword": "dotz",
  "peers": [ { "name": "work", "keyword": "work", "reply_prefix": "[work]" } ] }
```

- `name`: 목록에 보일 이름입니다(30자까지, 비우면 `keyword`). `keyword`: 그 컴퓨터가 읽는 키워드입니다(공백 없는 1~30자, 이 게이트웨이의 `keyword`와 같을 수 없고 겹치면 앞의 것만 씁니다). `reply_prefix`: 그 컴퓨터가 답할 때 글 맨 앞에 붙이는 말머리입니다(1~30자). 이 게이트웨이의 `reply_prefix`나 다른 컴퓨터의 머리말과 같을 수 없습니다. 웹 앱은 규칙에 맞지 않는 항목을 이유와 함께 거절하고, 설정 파일에서는 그 항목이 버려집니다. 최대 8개입니다.
- 채팅 화면에는 방의 최근 메시지 100개 중 본인이 쓴 `<keyword> …` 글과 `<reply_prefix> …`로 시작하는 답만 나옵니다. 글을 보내면 본인 이름으로 `<keyword> <내용>`이 그 방에 올라가고, 그 컴퓨터가 읽어 갑니다(1~4000자). 보낸 글이 방에 나타날 때까지는 `보내는 중…`으로 보입니다. 그 컴퓨터와 직접 통신하지는 않습니다.
- 이 채팅은 글만 주고받아요. 파일 첨부, 진행 표시, 결정 카드는 없고, 답에 `[file] …`나 `결정:` 블록이 들어 있어도 그냥 글로 보입니다. 화면 위쪽 안내 줄에도 이 내용이 적혀 있습니다.
- `연결됨` 표시는 최근 24시간 안에 `<reply_prefix>` 답이 방에 올라온 적이 있다는 뜻입니다. 오래 말이 없었거나 잔디를 읽지 못하면 `연결 안 됨`으로 보이지만, 눌러서 보낼 수는 있습니다.
- 옛 채팅 페이지 주소(`/jandi-peer/<keyword>`)는 이제 앱의 채팅 화면(`/#chat/relay:jandi:<keyword>`)으로 넘겨 줍니다. 저장해 둔 북마크는 그대로 써도 됩니다. 앱에서 이 채팅을 주소로 직접 열 수도 있습니다.
- 새 답이 올라오면 휴대폰으로 알려 줍니다. 제목은 그 컴퓨터 이름이고, 본문은 답의 앞 120자입니다. 알림을 누르면 그 컴퓨터의 채팅 화면이 열립니다. 답 맨 앞의 표시에 따라 `[ask]`는 답이 필요한 알림, `[done]`과 `[fail]`은 결과 알림, 표시가 없으면 일반 메시지로 갑니다. `[run]`으로 시작하는 진행 중 답은 알리지 않습니다. 앱의 알림 설정을 그대로 따르고, 그 컴퓨터의 채팅을 화면에 띄워 둔 동안에는 알리지 않습니다. 채팅을 열면 이미 온 알림은 모든 기기에서 닫힙니다. 글 하나에 알림 하나이고, 게이트웨이를 다시 켜도 같은 글을 또 알리지 않습니다. 알림이 필요 없는 컴퓨터는 목록에서 스위치를 끕니다(설정 파일로는 `"notify": false`).
- 이 목록과 채팅은 `self_chat.enabled`가 켜져 있고 `team_id`, `room_id`, `member_id`, `bot_id`가 모두 있을 때만 나오고, 소유자 로그인(기기 인증)을 거친 요청에만 열립니다. 읽는 방은 `room_id` 하나뿐이며, 처음 읽을 때 본인과 JANDI 봇의 1:1 대화방인지 확인합니다.
- 잔디 오류(세션 만료, HTTP 오류)는 빈 대화가 아니라 채팅 화면에 오류 줄로 보입니다. 보내기가 실패하면 쓴 글이 입력칸으로 돌아옵니다.

### 상태 요약

잔디로만 닿는 컴퓨터는 주소가 없어서 화면을 물어볼 수 없습니다. 그래서 그 컴퓨터가 자기 상태를 같은 방에 짧게 올리고, 읽는 컴퓨터가 그것을 보여 줍니다. Tailscale이나 다른 연결은 쓰지 않습니다.

- **보내는 쪽**: 그 컴퓨터의 **설정 > 메신저 > JANDI**에서 **이 컴퓨터 상태를 잔디로 보내기**를 켭니다(기본은 꺼짐, 설정 파일로는 `self_chat.share_status: true`). 답 머리말(`reply_prefix`)이 있어야 보냅니다. 켜면 프로젝트(이름, 메모, 진행 중 세션 수), 세션 상태, 모니터링 목록과 결과, 열린 할 일 수와 앞 5개, 최근 알림 5개를 `<reply_prefix> #dotz-status.v1 {…}` 한 줄로 올립니다. 내용이 바뀌었을 때만 30분에 한 번까지 올리고, 바뀌지 않아도 6시간에 한 번 올립니다. 모니터의 실행 시각만 바뀐 것은 바뀐 것으로 치지 않습니다. 마지막에 보낸 것은 데이터 폴더의 `messengers/jandi-snapshot.json`에 남아, 게이트웨이를 다시 켜도 같은 것을 또 올리지 않습니다.
- 요약에는 폴더 경로, 주소, 채널 번호를 넣지 않습니다. 모든 글에서 토큰과 저장된 비밀값은 가리고, 홈 폴더 경로와 메일 주소는 `…`로 바꿉니다. 한 줄은 3500자를 넘지 않고, 넘으면 긴 목록 끝부터 덜어 내고 `일부 항목은 빠져 있어요`로 알립니다.
- **읽는 쪽**: 요약 줄은 채팅에 나오지 않고 휴대폰 알림도 띄우지 않습니다. 컴퓨터마다 가장 새 요약을 데이터 폴더의 `messengers/jandi-peer-status.json`(0600)에 남겨, 방의 최근 100개 밖으로 밀려나거나 게이트웨이를 다시 켜도 보여 줍니다. 앱은 `GET /api/relay/jandi/<keyword>/status`(`{ snapshot, received_at? }`)로 읽고, 화면을 보는 동안 30초마다 다시 읽습니다.
- 홈에는 세션, 할 일, 최근 알림이, 프로젝트에는 그 컴퓨터의 프로젝트가, 모니터링에는 그 컴퓨터의 모니터가 보이고, 맨 위에 `마지막 갱신 …`이 있습니다. 실행, 일시 정지, 편집 같은 단추는 없고, `읽기 전용이에요. 바꾸려면 채팅으로 요청해요`와 채팅 열기 단추만 있습니다. 아직 요약을 받지 못했으면 그 컴퓨터에서 스위치를 켜라는 안내가 보입니다.
- 프로젝트 목록의 컴퓨터별 묶음에도 그 컴퓨터가 요약 속 프로젝트와 함께 올라옵니다. 그 프로젝트를 누르면 다른 주소로 넘어가지 않고 그 컴퓨터의 읽기 전용 프로젝트 화면이 열립니다.
