# Slack 연결 (온보딩)

설정 → Slack 화면의 **연결**을 누르면 dotz가 Slack 앱과 봇 토큰을 준비합니다. 토큰을 먼저 붙여 넣을 필요가 없습니다. 이미 있는 설정과 `~/.dotz/secrets/slack-bot-token`을 먼저 재사용합니다.

## 온보딩이 하는 일

1. 저장된 봇 토큰과 `~/.dotz/messengers/slack.json`을 확인합니다. 토큰이 있으면 `auth.test`로 바로 검증합니다.
2. 토큰이 없으면 오너의 Aside 브라우저(백그라운드)에서 Slack 앱을 만듭니다. 앱 매니페스트에 필요한 권한만 넣습니다: `chat:write`, `channels:read`, `users:read`.
3. 오너가 워크스페이스에 앱을 설치(**허용**)하면 브라우저에서 봇 토큰을 읽어 `secrets/`에 0600으로 저장합니다.
4. `conversations.list`로 채널을 읽어 웹앱 구조에 맞춰 매핑합니다: 메인 대화, 알림, 작업 기록. 프로젝트 채널은 이름이 맞는 것을 찾고, 없으면 메인으로 보냅니다.
5. 채널 매핑과 허용 사용자(오너)를 설정 파일에 저장하고 알림 라우팅을 켭니다.

## 오너가 하는 일

- Slack 로그인과 2단계 인증
- Slack 앱 설치 화면의 **허용** 클릭
- 워크스페이스 관리자 승인이 필요한 경우 그 승인

화면에 한 단계로 표시됩니다. 끝나면 dotz가 이어서 진행합니다.

## 저장되는 것

| 무엇 | 어디 | 권한 |
| --- | --- | --- |
| 봇 토큰 | `~/.dotz/secrets/slack-bot-token` | 0600 |
| 봇 토큰, 채널 매핑, 허용 사용자 | `~/.dotz/messengers/slack.json` | 0600 |
| 온보딩 진행 상태(비밀 없음) | `~/.dotz/onboarding/slack.json` | 0600 |

## 복구와 연결 끊기

- **직접 입력**을 열면 봇 토큰과 채널 ID를 직접 넣을 수 있습니다. Slack 앱 화면이 바뀌어 자동화가 실패했을 때의 복구 경로입니다.
- **연결 확인**은 `auth.test`로 토큰과 워크스페이스를 확인합니다.
- **연결 끊기**는 `~/.dotz/messengers/slack.json`을 지웁니다. Slack 쪽 앱은 Slack 관리 화면에서 직접 제거합니다.
- 온보딩이 실패하면 이유 한 줄과 다음 할 일 한 단계가 표시됩니다. **연결**을 다시 누르면 저장된 것부터 이어서 합니다.

## 한계

- 지금 Slack은 **보내기**만 합니다. dotz 답장과 알림은 Slack 채널로 가지만, Slack에서 보낸 메시지를 dotz가 읽어 답하는 흐름은 아직 없습니다. 대화는 웹앱에서 이어서 합니다.
- Socket Mode나 Events API 수신 주소를 쓰지 않습니다. 공개 URL이 필요 없습니다.
- 봇은 초대된 채널만 볼 수 있습니다. 채널을 추가한 뒤 **연결 확인**을 누르면 목록이 갱신됩니다.
- 사용자 토큰은 쓰지 않습니다. 항상 봇 토큰입니다.
- 한 워크스페이스만 연결합니다. 여러 개가 필요하면 설정 파일을 나누는 별도 작업이 필요합니다.
