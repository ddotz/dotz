# dotz 엔지니어링 기준

속도, 안정성, 기술부채, 코드 꼬임, 중복을 재는 기준이에요. 값은 2026-11-05에 main(`cd480cec` 기준)에서 잰 수치에서 정했어요. 이 머신은 측정 내내 다른 세션이 돌아 부하 평균이 8-50이었으니, 시간 값은 바쁜 맥북 기준으로 읽어요.

강제 방식은 `hub/design-rules-web.test.ts`와 같아요. 코드로 잴 수 있는 기준은 `hub/engineering-rules.test.ts`가 지켜요. 지금 위반은 개수 상한으로 동결해서 새 위반만 실패해요. 고치면 상한을 내리고, 변경을 통과시키려고 올리지 않아요. 지금 값은 `bun hub/engineering-rules.ts`로 봐요.

게이트로 걸기에는 흔들리는 값이에요. 크게 바꾸는 변경 전후로 재고, 기준을 넘으면 그 변경에서 원인을 찾아요.

## 코드로 못 잡는 약속

- 새 기능 전에 같은 일을 하는 기능을 찾아요. `docs/ARCHITECTURE.md`를 먼저 보고, 없으면 같은 데이터를 읽는 화면과 같은 동작을 끝내는 경로를 `grep`해요. 두 번째 경로를 만들면 첫 경로를 지우거나, 왜 둘이어야 하는지 브리프에 적어요.
- 보내기 경로는 하나의 확인을 지나요. 승인 판정은 `hub/draft-approval.ts`, 중복 발송 방지는 `claimSend`예요.
- 오류는 처리하거나, 기록하거나, 왜 무시해도 되는지 주석을 남겨요. 사용자 작업을 잃는 실패는 삼키지 않아요.
- 시험은 혼자 돌 때와 `--parallel=4`에서 둘 다 통과해야 해요. 시간을 재는 시험은 시간 자체가 동작일 때만 쓰고, 나머지는 호출 횟수나 사건을 세요.

## 기준을 바꿀 때

상한은 `hub/engineering-ceilings.json`에 있고, 올리지 않는다는 약속은 코드가 지켜요. `.githooks/pre-push`가 푸시되는 커밋의 이 파일을 푸시 대상 원격 main(main으로 푸시하면 그 원격의 현재 커밋, 아니면 `<원격>/main`)의 같은 파일과 비교해서, 상한이 올랐거나 기준에 없는 새 키가 있으면 `ceiling raised <키>: 전 -> 후` 한 줄씩 찍고 푸시를 거절해요. 낮추거나 키를 지우는 건 허용해요. 기준을 못 읽으면(원격 ref 없음, 첫 푸시, 얕은 복제) 막지 않고 경고 한 줄만 찍어요. 기준값을 바꿀 때는 이 문서의 현재값도 다시 재요.
