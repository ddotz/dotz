# dotz UI 원칙

소개 페이지 "이렇게 써요" 데모 카드(`site/stageshow-src/cards.tsx`, `cards.css`, `look.css`)와 젠틀 UI 작업에서 뽑은 원칙이에요.
웹 앱(`web/`)의 모든 화면이 이 원칙을 따라요. 색, 글자 크기, 모서리 같은 토큰은 `web/DESIGN.md`, 움직임 도우미는 `web/js/01-motion.js`에 있어요.

## 원칙

1. **주인공은 하나예요.** 한 화면, 한 카드마다 가장 먼저 보여 줄 정보 하나(제목, 지금 값, 내가 누를 것)를 정하고, 그것만 진한 글씨와 큰 크기를 가져요. 나머지는 회색 단계(`--fg-2`, `--fg-3`)와 여백으로 물러나고, 두 덩어리가 같은 세기로 다투지 않아요.
2. **지금 봐야 할 것만 진하게 해요.** 새로 온 것, 내가 답할 것, 바뀐 값만 굵게 하거나 강조색을 써요. 바뀌기 전 값은 회색 취소선으로 옆에 둬요(`89,000원 → 72,000원`).
3. **정보는 구조로 보여 줘요.** 일정은 "시각 + 제목" 행, 메일은 "보낸 사람 + 한 줄 요약" 행, 결과는 파일 칩, 개수는 숫자로요. 모양이 있는 내용을 날 글이나 로그로 두지 않아요. 원문과 로그는 펼쳐야 보여요.
4. **행 하나는 한 줄 요약이에요.** 왼쪽에 아이콘이나 상태 점, 가운데에 굵은 제목과 그 아래 한 줄 요약(출처 · 내용), 오른쪽 위에 시각(방금, 오전 8:00, 어제)이에요. 두 줄을 넘기지 않아요.
5. **남의 글은 조용한 인용, 내가 할 일은 카드예요.** 댓글, 메일 원문, 받은 메시지는 아바타와 옅은 글씨의 인용으로 두고, 초안이나 결정처럼 내가 누를 것만 카드와 버튼을 가져요.
6. **상태는 그 자리에서 바뀌어요.** 보내기 → 보냈어요, 진행 중 → 완료처럼 같은 칸 안에서 겹친 층만 바꿔요. 아래 내용이 밀리거나 카드가 새로 생기지 않아요.
7. **끝난 일은 결과물로 끝나요.** 작업이 끝나면 완료 표시 옆에 결과 파일이나 링크를 칩으로 붙여요. "완료"라는 글자만 남기지 않아요.
8. **움직임은 원인이 있을 때만이에요.** 도착하면 떠오르고(`motionIn`), 새 행은 목록 맨 위로 미끄러져 들어오고(`motionIn(el, "top")`), 상태는 제자리에서 바뀌고(`motionSwap`), 떠나면 사라지고(`motionOut`), 숫자는 바뀐 자리만 굴러요(`rollCount`). 200-300ms, 처음 그릴 때는 움직이지 않고, 동작 감소 설정이면 바로 바뀌어요. 반복하거나 꾸미는 움직임은 없어요.
9. **테두리와 그림자 대신 여백과 회색 단계예요.** 카드는 바탕색 차이로 구분하고, 목록 안에서만 얇은 구분선을 써요. 그림자는 떠 있는 메뉴와 창에만 써요. 지메일식 메일 목록의 한 장 구분선은 그대로 둬요.
10. **종류는 작은 알약 태그로 말해요.** "아침 점검", "유튜브 댓글"처럼 이게 무엇인지는 제목 옆 작은 태그나 메타 줄로 알려요. 색은 강조색 하나만 써요(상태 색 규칙은 `web/DESIGN.md`).
11. **글은 구절 단위로 끊어요.** 넷플릭스 자막처럼 어절과 구절 사이에서만 줄을 바꾸고(`keep-all`), 제목과 짧은 안내는 줄 길이를 맞춰요(`balance`). 채팅창 안의 글(답, 카드, 안내)은 구절로 묶지 않고 보통 줄바꿈을 따라요. 문장은 짧은 해요체예요.
12. **봇이 쓴 글은 바꾸지 않고 모양만 입혀요.** 일정, 메일 요약, 개수처럼 모양이 읽히는 답은 행과 칩으로 그리고, 모양이 없으면 평소 글로 둬요.
13. **없는 요소의 자리는 남기지 않아요.** 제목, 부제, 개수, 배지, 아이콘처럼 빠질 수 있는 요소가 없으면 남은 요소가 스스로 다시 흘러 정렬돼요. 빈 칸이나 여백을 예약해 두지 않고, 부제 없는 행은 제목이 세로 가운데에 서요. 내용이 찬 상태와 빈 상태를 둘 다 확인해요.
14. **같은 말을 두 번 하지 않아요.** 제목, 태그, 부제, 버튼 라벨이 같은 뜻을 되풀이하면 하나만 남겨요. 점이나 아이콘이 이미 말한 상태를 글자로 다시 쓰지 않아요(진행 점 옆의 "진행 중" 태그 같은 것).
15. **한눈에 읽히는 건 글자 대신 점·아이콘·색이에요.** 상태(진행·내 차례·실패·완료)는 상태 점의 색으로, 닫기·뒤로·더 보기·검색 같은 흔한 동작은 아이콘으로 보여 줘요. 글자를 뺀 자리에는 `aria-label`이나 `title`을 남겨 뜻이 그대로 전해지게 해요. 시각, 개수, 이름처럼 읽어야 아는 건 글자로 둬요.
16. **강조색은 누를 것에만 써요.** 강조색은 주요 버튼, 선택된 것, 진행 표시에만 쓰고 한 화면 넓이의 10%를 넘기지 않아요. 날짜, 체크, 숫자, 아이콘을 강조색으로 칠하지 않아요(안 읽은 숫자 배지 `.nb`의 바탕만 예외예요). 그 밖의 색은 상태 색까지 다섯 가지 안에서 강조색보다 약하게 써요.
17. **카드는 할 일과 핵심 정보에만 써요.** 항목을 나누려고만 카드를 쓰지 않아요. 관련된 것은 한 묶음으로 모으고, 묶음 사이 여백과 글자 크기·굵기로 순서를 보여 줘요. 카드 안에 또 카드를 넣지 않고, 아이콘 뒤에 옅은 색 상자를 깔지 않아요.

## 데모 카드 ↔ 앱 화면

| 데모 카드 | 앱 화면 | 핵심 원칙 |
|---|---|---|
| 아침 점검 | 채팅의 브리핑 답(결과 카드), 홈 | 3, 4, 10, 12 |
| 댓글 답글 | 모니터링 댓글·DM, 답글 초안 카드 | 5, 6 |
| 가격 알림 | 알림 목록, 감시 변화 알림 | 2, 4, 8 |
| 작업 완료 | 홈의 진행 중·최근 끝난 작업, 채팅 결과 카드 | 6, 7 |
