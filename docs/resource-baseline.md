## 근거를 재서 고치지 않기로 한 후보

- 킵얼라이브: 7일 158턴, 28.2M 토큰이고 전부 할 일 없는 턴입니다. 그래도 한 번의 캐시 재작성이 18번 분량이라 줄이면 손해입니다.
- 감시: 최근 7일 실패가 1건입니다.
- 첫 화면과 화면 전환: 이미 100ms 아래입니다.
- 게이트웨이 누수: 없습니다. 메일 320통과 API 1,600번을 6번 반복해도 정착 RSS가 309, 426, 465, 371, 283, 311MB로 오르내리고 계속 오르지 않습니다. RSS보다 실제 물리 사용량(`phys_footprint`)이 낮습니다. 반복 뒤 RSS 411MB일 때 158MB, 실사용 게이트웨이는 137MB입니다.
- 유휴 GC와 `--smol`: 실사용 RSS가 287MB에서 80MB대까지 저절로 내려가고 위 물리 사용량도 낮아서 유휴 GC는 따로 재지 않았습니다. senpi 호스트에 `--smol`을 주면 164MB 대 165MB로 차이가 없고 래퍼 프로세스 12MB가 늘어서 뺐습니다.
- 대기 프로세스 풀: 모델 프로세스는 10분 유휴에 종료, 레인은 20분 유휴에 정지, 대화 세션은 압박 때 1분 유휴로 정리됩니다. 상한이 이미 있습니다. 메모리 가드도 재시작을 일으키지 않았습니다.
- 웹 폴링: 탭을 켜 둬도 서버 CPU가 1.3%, 닫으면 1.2%입니다. 1분 요청 18번의 합이 1초 미만이라 줄여도 체감이 없습니다.
- 웹 유휴 긴 작업: 기계가 바쁠 때 재면 1분에 16번 6.9초였지만 조용할 때는 4번 297ms입니다. 시험 부하 때문이지 화면 문제가 아닙니다.
- `claude-sdk-oauth-binding`이 토큰 감사의 캐시 깨짐 원인처럼 보이지만 이 기록은 턴마다 남는 표시입니다(7일 8,836건). 감사 쪽 표시 오류입니다.
