## 출력 줄이기 (11-05 재서 고침, 최근 3일 레인·워커 세션 375개)

- 분리 실행(detached eval) 완료 알림은 도구 결과가 아니라 `senpi-codemode:notification` 메시지라서 출력 상한을 지나지 않았습니다. 알림 줄 505건·7.7M자는 같은 알림이 work-custody 기록에 대기·소비·완료로 세 번 더 남은 것까지 센 값이고, 모델이 읽는 알림은 399건입니다. 그중 글자는 666K자뿐이고 나머지 3.5M자는 base64 그림 9개(글자 아님)입니다. 20K자를 넘는 알림은 3건(최대 34K자), 10K자 넘는 것은 13건입니다. 모델에 가는 최대치가 2.34M자가 아니라 34K자라는 뜻입니다.
- 고침: `extension/output-cap.ts`가 `context` 훅에서 알림도 같은 20K자(머리 15K + 꼬리 5K)로 줄입니다. 알림은 이 훅에서 `customType` 없는 user 메시지라서 첫 글자(`<system-reminder>Detached eval cell `)로 알아봅니다. 같은 알림은 매 요청에 같은 글자가 되어 프롬프트 캐시가 깨지지 않습니다. 줄인 자리의 노트가 전체 출력 파일 경로를 알려 줍니다(런타임 `[Full output: …]` 줄이 있으면 그것을 그대로 둠). eval·bash 결과도 같은 노트를 씁니다.
- 실제 세션(rpc 모드, 워커 환경): 알림이 모델 요청에서 46,081자 → 20,229자. 전체는 노트가 가리키는 파일에 있습니다.
- 한 번에 드는 값: 알림이 20K자를 넘는 일이 3일에 3번이라 아낀 양은 약 26K자(×남은 턴)로 작습니다. 구멍을 닫는 값은 작지만 위험(캐시·검증)도 없습니다. 꼬리 5K자에 오류 줄·테스트 요약·`Kernel state updated`가 남습니다.
