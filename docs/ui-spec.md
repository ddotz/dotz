# dotz UI 명세 (표시 형태별)

일부 규칙은 Stageshow(benjitaylor/skills, MIT)의 craft·motion 지침을 앱에 맞게 옮겼어요.

`docs/ui-principles.md`의 12원칙을 형태마다 숫자로 옮긴 거예요. 토큰 값은 `web/css/01-tokens.css`(같은 표가 `web/DESIGN.md`), 코드는 `web/css/*.css`에 있고, 화면은 여기 적힌 클래스만 써요. 화면마다 높이나 여백을 따로 고치지 않아요(고칠 게 있으면 이 명세와 공용 클래스를 고쳐요).
각 규칙은 이유를 달았어요. 숫자는 앱이 이미 가장 많이 쓰는 값에서 골랐어요.

**채팅창 글에는 구절 묶음을 걸지 않아요.** 넷플릭스 자막식 줄바꿈(`.wph`)은 설정·안내 글에만 쓰고, 채팅창(`#tl`)의 답과 카드, 그리고 시트의 본문(`.md`)·질문·선택지 설명처럼 에이전트가 쓴 글은 보통 줄바꿈을 따라요. 이유: 형이 채팅에서는 어색하다고 했고(11-03), 긴 문장을 묶으면 묶음마다 줄이 끊겨요(11-05).

## 토큰

시제품(`site/prototype/proto.css`)의 기반을 앱 토큰으로 옮겼어요. 색은 라이트·다크를 따로 조율한 두 벌이고(테마 전환은 지금처럼 `data-theme`, 저장값이 없으면 시스템 설정), 아래 값은 두 테마가 같이 써요. 화면은 이 이름만 쓰고 숫자를 직접 적지 않아요.

**높이** (`web/css/01-tokens.css`)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--row-h` / `--row-py` / `--row-px` | 44px / 8px / 16px | 목록 행·설정 행(`.li`), 목록 성격의 행 |
| `--menu-h` / `--menu-py` / `--menu-px` | 30px / 4px / 8px | 팝오버 메뉴 항목(`.mi`) |
| `--menu-h-sheet` | 44px | 폰 시트 안 메뉴 항목(`.menu.msheet .mi`) |
| `--sheet-h` | 44px | 시트 안 고르는 항목(`.ds-opt`, `.ds-direct`) |
| `--btn-h` | 36px | 기본 버튼(`.btn`) |
| `--btn-h-sm` | 32px | 작은 버튼(`.btn.sm`), 카드 아래 줄(`.cf`) |
| `--btn-h-row` | 28px | 행 안 버튼(`.btn.inrow`) |
| `--btn-hit` | 44px | 터치 화면의 누르는 영역(보이는 상자는 그대로) |
| `--ctl-h` | 32px | 설정 행 오른쪽 입력칸·고르기(`.li-end .fi`/`.sel`) |
| `--field-h` / `--field-h-touch` | 36px / 40px | 일반 입력칸·고르기(`.fi`, `.sel`), 터치 화면 |
| `--chip-h` / `--tag-h` | 28px / 20px | 칩(`.chip`), 상태 태그(`.tag`) |

행 안 버튼(28px)은 보이는 상자를 낮추고 `::after`로 위아래 8px씩 눌리는 영역을 넓혀 터치 44px을 지켜요. 기본 버튼은 터치 화면에서 44px(`--btn-hit`)이에요. 이유: 목록이 한눈에 들어오면서도 손가락으로는 놓치지 않아요.
폰에서 44px보다 작게 그려진 컨트롤은 보이는 크기는 그대로 두고 눌리는 영역만 44px 이상으로 넓혀요(`::after`, 또는 가로로 스크롤되는 줄은 안 여백과 같은 크기의 음수 마진). 이웃 컨트롤의 영역과 겹치지 않아야 해요. 이유: 키우면 화면이 달라 보이고, 영역이 겹치면 엉뚱한 컨트롤이 눌려요.

**모서리**

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--r-card` | 18px | 카드, 목록, 카드 안 목록 |
| `--r-sheet` | 20px | 시트·대화창(`.fs-card`, `dialog.dlg`) |
| `--r-menu` | 14px | 팝오버 메뉴, 떠 있는 알림 |
| `--r-ctl` | 10px | 버튼, 입력칸, 칩, 탭, 말풍선, 메뉴 항목 |
| `--r-seg` / `--r-seg-in` | 8px / 6px | 분할 컨트롤 바탕 / 고른 칸(바깥 = 안쪽 + 2) |
| `--r-pill` | 999px | 작은 상태 태그(`.tag`)와 두 값 토글(`.chip.tgl`)에만 |

**움직임**

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--m-fast` | 150ms | 누름·올림, 사라짐, 작은 전환 |
| `--m-base` | 220ms | 도착·제자리 바뀜, 시트 열림 |
| `--m-slow` | 300ms | 큰 면, 진행 막대(`.bar i`) |
| `--m-ease` | `cubic-bezier(.2, .7, .2, 1)` | 모든 전환·애니메이션, `web/js/01-motion.js`의 `M_EASE` |

`prefers-reduced-motion: reduce`이면 모든 전환·애니메이션(가상 요소 포함)이 `none`이 되고 JS 도우미는 바로 최종 상태를 만들어요. 제품에는 모션 켜기/끄기 설정을 두지 않아요.

**글자·여백**: `--fs-page` 22/30, `--fs-card` 16/22, `--fs-row` 15/22, `--fs-body` 14/22, `--fs-meta` 12/16, `--fs-tag` 11/16. 여백은 `--sp-1` 4px부터 `--sp-8` 32px까지 4px 단계예요.

## 상태·필터·화면 탭 (알약 없음)

**완전히 둥근 알약은 쓰지 않아요(형 결정: 점 + 글자, 화면 탭은 밑줄).** 상태는 색 점 + 글자, 목록 보기 고르기는 한 줄 분할 트랙, 화면 전체를 바꾸는 탭은 밑줄이에요. 언제 무엇을 쓰는지는 `web/DESIGN.md`(상태·필터·화면 탭)에 있어요.

버튼, 설정 안의 칩(`.chip`), 탭(`.ni`, 대화 전환 칩), 말풍선(`.ub`, 카카오 `.kk-bub`)은 `--r-ctl` 10px이에요. 큰 모서리(16~999px)를 새로 만들지 않아요. 이유: 모양이 늘어나면 무엇이 상태이고 무엇이 누르는 것인지 흐려져요. 개수·점 배지(`.nb`, `.dot`)는 숫자·점 모양 그대로예요.

## 공통 규칙

모든 형태에 걸리는 규칙이에요. 형태별 절에는 그 형태에서 특히 중요한 것만 다시 적었어요.

**여백과 정렬**
- 글자는 카드·행·시트·눌린 행 가장자리에서 가로 12px 이상 떨어져요(앱 기본은 행 16px, 카드 20px). 8px 밑이면 붙어 보여요. 막대와 구분선만 가장자리까지 가요.
- 행 안 여백은 위아래 8px(`--row-py`), 촘촘한 목록은 6px. 한 줄 행이 글자 높이의 3배를 넘으면 뚱뚱해 보여요. 공기는 행 안이 아니라 행 수로 채워요.
- 제목과 부제는 한 덩어리: 사이 4~6px, 줄 높이 1.3 이상. 이유: 떨어지면 두 항목으로 읽혀요. 덩어리 사이는 이보다 넓게(8px 이상) 둬요.
- 버튼은 위의 입력칸·선·카드 가장자리에서 8px 이상 떨어져요. 이유: 닿으면 하나로 붙어 보여요.
- 이웃한 상자와 글자 사이는 간격 8~12px을 정해서 줘요(`space-between` 남는 틈 금지). 한 묶음(`.chips` 4px, `.seg` 2px, 아이콘+글자 6px)만 예외예요.
- 안에 든 모양은 사방 같은 여백으로 감싸고, 바깥 모서리 = 안쪽 모서리 + 여백이에요(`.seg` 8px = 6px + 2px). 이유: 어긋나면 모서리 사이가 두꺼워 보여요.
- 컨트롤은 내용만큼만 차지해요(`flex: 1`로 늘리고 내용을 한쪽에 몰지 않아요). 이유: 한쪽만 빈 버튼은 어긋나 보여요. 좌우 안 여백 차이는 4px 이하.
- 같은 목록의 행은 열 칸이 같아요: 아이콘 칸, 글 칸, 오른쪽 칸이 모든 행에서 같은 x에 서요. 점·배지는 열이 아니라 아이콘 칸이나 글 앞에 6px 띄워 놓아요.
- 거의 닿는 선 금지: 가장자리는 정확히 맞추거나 8px 이상 띄워요(1~3px 차이는 실수로 보여요).
- 마우스를 올린 행과 고른 항목의 바탕은 안쪽으로 들이고 모서리를 둥글게 해요(`--r-ctl` 10px). 링크는 올려도 바탕이 없고, 컨트롤은 가만히 있을 때 이미 보여요.

**글자**
- 화면 글자는 11~15px(예외: 페이지 제목 20~22, 큰 값 20). 한 가지 글꼴(Pretendard). 코드와 경로만 `--mono`.
- 줄 높이는 글자의 1.3배 이상. 위계는 여백과 **한 단계 굵기 차이**(400/500 본문 ↔ 600 제목)로 만들고 700은 큰 값과 페이지 제목에만.
- 한 카드에서 진한 글자는 하나(원칙 1). 문장은 짧은 해요체.

**색**
- 잉크는 글자 3단(`--fg`, `--fg-2`, `--fg-3`) + 선 2단(`--line`, `--line-2`) 다섯에 강조색 하나(`--accent`). 상태색은 상태만 뜻해요.
- 테두리는 채움만으로 모자랄 때(입력칸 가장자리, 구분)만. 채움으로 되는 곳에 테두리를 덧대지 않아요.
- 채운 버튼은 올려도 자기 색 한 단계만 바뀌어요(`opacity .85`). 회색으로 바뀌지 않아요.
- 어두운 테마의 깊이는 더 밝은 바탕(`--card` → `--pop`)으로 만들고, 그림자는 보조예요.

**아이콘**
- 아이콘은 `icon()`(`svg.ic`) 한 벌만: 선 굵기 1.75(작은 아이콘은 2), 크기는 14·16·20px 셋뿐(기본 16, 앱바·아래 탭줄·큰 단추 20, 작은 칩·닫기 14). 18·22 같은 중간 값은 쓰지 않아요. 손으로 그린 아이콘과 이모지를 아이콘 자리에 쓰지 않아요(이모지는 내용일 때만).
- 14px 이하 아이콘은 선을 2로 두껍게 해요(`.mr-draft .ic`). 이유: 얇은 선은 작을 때 가늘어 보여요.
- 아이콘 상자는 `flex: none`, 짝수 크기. 색은 한 가지 불투명 색(`currentColor`), 흐리게는 `opacity`로.
- AI 장식(반짝이·마법봉)을 쓰지 않아요. AI가 하는 일을 보여 줘요.

**움직임**
- 원인이 있을 때만(도착, 제자리 바뀜, 떠남, 숫자 바뀜). 빈 반복·장식 금지.
- 시간 150~300ms(`--m-fast` 150 누름·올림, `--m-base` 220 도착·바뀜, `--m-slow` 300 큰 면), 곡선 `--m-ease`. 누르면 바로 반응해요(지연 없이 시작).
- `transform`과 `opacity`만 움직여요(예외: 진행 막대 너비, 스크립트가 자리를 정하는 보드 카드 `.bi`와 원문 옆 칸). 바탕색·글자색·테두리색은 서서히 바뀌지 않고 바로 바뀌어요(hover 포함). 글자는 늘어나지 않아요.
- 올렸을 때 바뀌는 글자색·바탕·테두리·그림자·투명도(`:hover`)는 `@media (hover: hover)` 안에만 둬요. 폰은 손가락이 마지막으로 닿은 곳에 hover를 남겨서, 누른 뒤에도 그 색이 남아요(`hub/hover-touch-css.test.ts`).
- 상태는 제자리에서 바뀌어요(`motionSwap`): 틀·정렬·버튼 자리는 그대로, 안쪽만. 바뀐 부분만 움직여요(`rollCount`는 바뀐 자릿수만).
- 화면 전체를 옆으로 밀지 않아요. 화면이 바뀌면 본문이 200ms 동안 겹쳐 바뀌며 8px 떠올라요(`motionIn`).
- 나타나는 것은 나타날 때 움직이고 사라지는 것은 `motionOut`이 끝난 뒤에 지워요(깜빡 나타나기 금지). 창·시트·카드는 투명해지며 겹치지 않고 움직이며 불투명하게 와요.
- 열린 메뉴·팝오버는 열린 쪽 가장자리에 고정되고, 열리는 동안 크기를 바꾸지 않아요.
- 결과를 보여 준 뒤에는 멈춰요(새 펄스·반복 숫자 없음). 동작 감소 설정이면 모두 바로 바뀌어요.

## 목록 행

**언제**: 같은 종류가 여러 개 줄지어 있고 하나씩 누르거나 훑을 때(메일, 세션, 계정, 설정 항목).
**생김새**
- `.list`(안쪽 `--r-card` 18px, `--card`) 안의 `.li`. 최소 높이 44px, 안 여백 8px 16px, 칸 간격 12px.
- 왼쪽 `.lead`(16px 아이콘, `--fg-3`) 또는 `.dot`(8px, 글자와 6px 이상), 가운데 `.tx` = `.hd` 15/22 500 `--fg` + `.sup` 12/16 `--fg-2` 한 줄(제목과 4px), 오른쪽 시각이나 `.tag`(12px `--fg-3`).
- 줄 구성(왼쪽 점·제목, 오른쪽 끝 상태·시각, 그 앞의 표시)은 `web/DESIGN.md`의 목록 줄 구성 하나를 따라요.
- 모든 행의 아이콘·글·오른쪽 칸이 같은 x에 서요. 행 사이는 1px `--line` 한 줄뿐. 누르는 행은 `button.li`, 올리면 `--card-hover`.
- 선택된 행(`.on`)과 누르는 중인 행(`:active`)의 바탕은 `--row-sel` 하나예요(라이트 #e8ebee, 다크 #2b2b31). 바깥 페이지 바탕(`--bg`·`--layer`)이나 카드 바탕(`--card`)과 같은 값을 쓰지 않아요. 카드(`.list`, `.pl-list`)는 `overflow: hidden`과 `--r-card`로 첫 행·마지막 행의 바탕을 둥근 모서리에 맞춰 잘라요. 그래서 맨 위나 맨 아래 행을 골라도 카드 모서리가 떨어져 나가 보이지 않아요. 프로젝트·메일·알림·설정 목록이 이 토큰 하나를 따라요(`hub/ui-rules-web.test.ts`가 확인).
- 목록의 더 보기(`moreRow`, `.cv-more`)는 카드의 마지막 줄이에요: 카드 안, 위에 `--line` 구분선, 폭 전체가 누르는 자리(높이 44px 이상), 가운데 회색 글씨(`--fg-3`, hover `--card-hover`). 아이콘과 쉐브론이 없어 행으로 읽히지 않고, 카드 밖에 따로 띄우지 않아요. 프로젝트 목록은 마지막 묶음 카드, 채팅 목록은 프로젝트 카드, 내 규칙은 그 카드에 붙어요.
- 여러 개를 켜고 끄는 고르기 목록(카카오톡 지켜볼 대화방)은 행 전체가 버튼이에요(`role="checkbox"`, `aria-checked`). 누르면 켜지고 다시 누르면 꺼져요. 켠 행은 선택된 행 바탕(`--row-sel`)과 오른쪽 끝의 작은 `check` 아이콘(강조색)뿐이고, 끈 행에는 아무것도 두지 않아요. 행 안에 스위치나 따로 누르는 아이콘을 두지 않고, 되돌릴 수 있으니 확인창도 없어요.
- 제목은 한 줄이고, 넘치면 끝이 흐려져요(`web/css/25-list-title.css`, 새 목록 제목은 여기 선택자에 더해요). 흐림은 상자의 오른쪽 여백 안에 있어서 다 들어가는 제목은 건드리지 않아요. 잘린 제목 전체는 행을 열거나 `title`로 봐요. 요약은 두 줄까지. 줄은 어절 사이에서만 바뀌어요(`keep-all`). 새 행은 `motionIn(el, "top")`, 사라지는 행은 `motionOut`.
- 모니터링은 폭과 상관없이 폰과 같은 흐름이에요(형 결정 2026-11-04, 예전의 PC 세 단을 대신해요). 목록은 페이지 폭(920px)으로 혼자 서고, 앱이나 항목을 열면 목록은 화면에서 빠지고 위에 "‹ 모니터링"이 생겨요. 뒤로·브라우저 뒤로·주소(`#monitoring`, `#monitoring/<항목>`)가 같은 길이고 목록은 스크롤 자리를 지켜요.
- 모니터링 줄의 상태: 오른쪽 끝에는 점 + 짧은 말 하나만 있어요(`● 정상`). 고르는 순서는 `꺼짐`(내가 꺼 둔 것, 컴퓨터가 돌아와도 그대로예요) > `연결 안 됨`(그 항목이 도는 다른 컴퓨터가 응답하지 않아서 나머지는 예전 값이에요) > 항목 자체의 상태(연결 끊김 > 실패 > 늦어짐 > 바뀜 > 정상 > 확인 필요, `monStatus`)예요. 컴퓨터 이름과 연결 안 됨은 오른쪽에 늘어놓지 않고 부제 맨 앞의 말로 써요(`맥북에서 돌아요 · 맥북 연결 안 됨`, 응답하면 `맥북에서 돌아요 · <마지막 소식>`). 앱 줄도 같아요(`pqStatus`, `pqWhere`). 기다림을 보여 줄 게 없는 모니터(꺼짐, 다음 실행 없음, 응답 없는 컴퓨터)는 빈 막대 대신 부제를 보여 줘요.
- 모니터 제목은 사람이 읽는 이름이에요. 앱 키(`kakao` 등)는 앱의 한국어 이름으로 바꿔요(`카카오톡 새 소식`, `hub/watchtext.ts` `plainLabel`). 저장된 이름도 게이트웨이가 켜질 때 고쳐요.
- 명령어와 파일 경로는 모니터링 화면에 나오지 않아요(`monHuman`). 예약 문구가 실행 프롬프트 전체여도 경로·명령이 나오기 전의 문장만 제목이 되고(`주간 점검 시간이에요`), 40자를 넘으면 첫 문장까지만이에요. 행의 소식 줄과 마지막 결과도 같은 규칙으로 걸러요. 괄호 안에 경로가 있으면 괄호째 빠져요.
- 마지막 정상은 실패 뒤에, 마지막 실행과 다를 때만 보여요(`monLastOk`). 정상인 모니터는 상태와 마지막 실행 시각이 이미 같은 말을 해요.
- 상세의 확인 기록 제목은 다른 섹션 제목과 간격이 같아요: 위 24px, 카드까지 8px.
- 메일 목록의 체크박스로 고르면 위 막대에 읽음·안 읽음·보관·답장 안 함·삭제가 떠요. 답장 안 함은 고른 메일 중 답장이 남은 메일이 있을 때만 보이고 그 메일에만 적용돼요(섞여 있으면 "답장 안 함 2"처럼 개수를 말해요, 폰에서는 아이콘 옆 숫자로요). 막대는 고른 게 있든 없든 한 줄에 같은 높이(PC 40px, 폰 44px)라서 고르거나 풀어도 첫 행과 체크박스가 움직이지 않고, 폭이 모자라면 줄을 바꾸지 않고 옆으로 밀려요. 이 메일함이 따라오지 않아도 막대에 안내 줄을 더하지 않고, 처리한 뒤 토스트로 한 번만 말해요. 답장 필요 목록에서는 고르지 않아도 "이 목록 전부 답장 안 함"이 있어요. 5개가 넘으면 먼저 묻고, 토스트의 되돌리기로 한 번에 돌아가요. 몇 개든 요청은 한 번(`POST /api/mail/fyi`)이고 메일을 보내거나 읽음 상태를 바꾸지 않아요. 읽음이나 삭제가 메일함까지 안 가는 소스(`mailAction` 없음)의 메일이 목록에 있으면 막대 위에 그 사실을 한 줄로 늘 보여 줘요. 고르기와 폴더에 따라 바뀌지 않아서 행이 움직이지 않아요.
- 열린 메일 위 막대(`.mtop`)에는 그 메일의 동작을 아이콘으로 하나씩 다 놓고 ⋯는 두지 않아요. 돌아가기는 머리의 뒤로 버튼이 맡아요. 폰에서도 아이콘은 36px이에요. 폰에서 누르는 자리는 위아래 44px, 옆으로는 그린 폭 그대로예요: 아홉 개를 44px로 넓히면 396px라 막대(334px)에 들어가지 않고, 넓힌 만큼 옆 단추를 덮어요.
- 앱의 목록 화면(메일 목록, 카카오톡 방 목록, 댓글 글 목록)은 PC 폭(1100px부터)에서 그 페이지 폭을 통째로 써요. 가운데 좁은 단(`--col`)에 가두지 않고, 칩 줄·개수 줄·행이 같은 왼쪽 줄에서 시작하며 남는 폭은 제목과 미리보기가 받아요. 항목을 고르기 전에는 빈 상세 칸을 두지 않아요. 항목을 고르면 그때 전체 폭의 두 단(목록 300px + 상세)이 돼요. 폰은 그대로예요.
- 프로젝트 화면의 지금 상황은 그 프로젝트 대화가 남긴 것만 보여요: 요약 한 문장, 막힘·다음·정함 줄, 전체를 누르면 모두와 기억해 둔 말까지. 대화에서 끝난 일은 결과에 `대화`로, 주요 파일은 파일에 쉬운 이름으로 나와요(경로는 안 보여요). 대화 턴이 끝나면 스트림으로 바로 바뀌어요. 아무것도 없으면 빈 칸 안내 한 줄이에요.
- 커스텀의 내 규칙은 최근에 정한 5개만 보여요(`[MM-DD]` 기준, 날짜 없는 규칙은 맨 뒤). 더 있으면 프로젝트 목록과 같은 더 보기 `규칙 N개 더 보기`가 검색이 있는 전체 목록(`pmSheet`, `cmRulesBody`)을 열어요. 행은 짧은 제목 한 줄(`~/.dotz/rule-titles.json`, 25자 이하, 없으면 앞 구절을 어절에서 끊어요)이고, 행을 누르면 그 규칙의 원문을 담은 대화 초안이 열려요. 행마다 수정 버튼을 두지 않아요.
- 커스텀의 내 기능은 오너가 직접 만든 기능만 보여요: `~/.dotz/features`의 폴더 중 배포 기능과 이름이 다른 것, 또는 같은 이름에 `custom: true`로 글까지 자기 것으로 덮어쓴 것이에요. 배포 기능을 켜기만 한 복사본(`enabled`만 바꾸는 스위치, `switchFile`)은 여전히 배포 기능이라 이 카드에 나오지 않고, 구성(`기능 폴더`, 출처 배포)과 설정에서 다뤄요. 그 켜기·끄기 요청은 개인 복사본을 가리키고 배포 파일을 가리키지 않아요.
- 채팅 답의 출처 목록은 목록 블록 틀(`.mlist.mlist-src`)의 낮은 링크 행이에요. `출처:`·`참고:`·`근거:`·`Sources:` 줄 아래의 링크 줄(맨 URL, `이름: URL`, `이름 - URL`, `[이름](URL)`), 또는 답 끝에 이어진 맨 URL 두 줄 이상이 대상이에요. `근거:` 목록은 항목이 모두 링크일 때만 행이 되고, `근거: a · b` 한 줄은 그대로예요. 28px 글자 칸, 이름이 있으면 이름 아래에 사이트와 경로 끝 두 칸, 없으면 사이트 이름(www 뺀 도메인) 아래에 경로 끝 두 칸을 URL 문자열로만 만들어요(가져오기·파비콘 없음). 전체 URL은 `title`과 잘린 선택용 글자(`.mlist-url`)에 있어서 메시지를 복사하면 원래 URL이 나와요. 행 글자에서 끌면 링크가 끌려 나가지 않고 글자가 선택되고, 그냥 누르면 열리고, 글자를 고른 뒤 누르면 열리지 않아요. 문장 안 링크는 그대로이고 메신저도 그대로예요.
**하지 말 것**
- 행마다 카드나 테두리를 두르지 마세요. 이유: 원칙 9, 구분선 한 장으로 충분해요.
- 행 안에 기본 크기 버튼을 넣지 마세요(`.btn.inrow`나 `.ib`). 이유: 36px 버튼은 44px 행을 꽉 채워 뚱뚱해 보여요.
- 행 높이를 늘려 공기를 만들지 마세요. 이유: 행 수와 구분선으로 리듬을 줘야 목록이 한눈에 들어와요.
- 제목에 굵은 글씨를 둘 이상 쓰지 마세요. 이유: 원칙 1, 눈이 갈 곳이 하나여야 해요.


## 알림 화면 (#notices)

**언제**: 종을 눌러 열어 시간순으로 알림을 훑고, 처리할 것만 골라 낼 때. 알림은 대화가 아니라 이 화면이에요(`#chat/alert` 주소도 이리로 와요). 대화 기록은 행에서 원본 메시지로 갈 때만 열려요.
**생김새**
- 위에서부터 필터 탭 `.nsc-f`(전체 · 답변 필요 · 결과 · 새 소식 · 경고. 높이 32px, 모서리 10px, 13/20, 고른 것은 `--fg` 채움에 600), 넓은 화면(640px부터)은 탭 줄의 오른쪽 끝에, 폰은 탭 아래 줄의 오른쪽 끝에 `모두 읽음`(읽을 것이 있을 때만. 폰에서 탭이 단추에 가려지지 않게 줄을 나눠요. 누르는 자리 44px. 안 읽은 수는 탭이 말하고 "안 읽은 알림 N개" 문장은 없어요), 그 아래 묶음.
- 묶음은 처리할 것 → 새 소식 → 지난 알림 순이고, 비면 제목도 내지 않아요. 묶음 제목은 `.sec`, 그 아래 `.list` 하나예요. 날짜 구분과 `.bm`은 없어요. 새 소식과 지난 알림은 50개씩 그리고 `N개 더 보기`로 불러요.
- 행 `.nsc-r`은 목록 행 규칙 그대로: 안 여백 8px 8px 8px 16px에 두 줄. 윗줄은 제목 `.hd` 15/22와 시각 `.t` 12/22, 아랫줄은 요약 `.nsc-s` 12/16과 종류 `.tag`. 왼쪽 점 `.dot`은 상태색만(주황·빨강·초록)이고 지난 알림에서는 회색이에요. 강조는 제목 굵기 하나: 안 읽으면 700 `--fg`, 읽으면 400 `--fg-2`. 태그는 색 없는 회색 알약.
- 결정 행의 요약은 결정 상태를 따라요(`nscDecLine`): 열린 것은 `답을 기다리고 있어요`, 답한 것은 `답했어요 · 고른 답`, 무시·기한 지남·답 없이 끝남은 그 말 그대로예요. 답한 결정이 기다린다고 읽히면 안 돼요.
- 오른쪽 칸은 언제나 하나(28px, 시각·태그와 같은 x)라 빈 칸이 없어요.
  - ▾(`.nsc-fold`): 반복이 접힌 행. 닫혀 있으면 아래, 펼치면 위를 가리켜요. 접힌 행에는 ✕가 없고 요약 앞에 `N번 · `이 붙어요. 펼치기만으로는 읽지 않아요.
  - ›(`.nsc-tr`): 답변 필요·로그인처럼 열어서 처리하는 행. 지울 수 없어요.
  - ✕(`.nsc-x`): 그 밖 모두. 뜻은 묶음이 정해요: 처리할 것(실패) = 처리했어요(`/handled`), 새 소식 = 읽음으로 표시, 지난 알림 = 지우기(`/dismiss`, 토스트의 되돌리기는 `/undismiss`).
- 읽음은 행을 누르거나 ✕와 모두 읽음을 눌러야 생겨요. 화면에 지나간다고 읽지 않아요. 모두 읽음은 지금 필터에 보이는 것만 `/api/notices/read`로 보내고 `/api/read`는 부르지 않아요. 답이 필요한 행은 안 읽은 채로 둬요.
- 행에서 들어간 곳의 뒤로가기는 알림으로 돌아와 필터와 스크롤을 지켜요. 종으로 다시 열면 전체로 시작해요.
**하지 말 것**
- 질문 하나는 항목 하나예요. 세션의 질문은 결정 카드 하나로만 생기고(보고 행을 따로 만들지 않아요), 답하면 알림·답변 필요·채팅에서 함께 사라져요. 카드 머리와 행 요약은 `프로젝트 · 세션`으로 무슨 일인지 말하고, 제목은 질문 한 줄, 버튼 설명은 그 답의 결과예요. 선택지 없는 세션 [ask]는 카드가 되지 않아요: 세션에 한 번 돌려보내고, 다시 와도 평범한 글로만 남겨요. 카드가 열려 있는 동안 "기다리는 중" [ask]는 버려요.
- 안 보는 동안 끝난 대화의 답(메인, 메일, 프로젝트, 모니터링 대화)은 대화마다 행 하나로 새 소식에 들어오고 종 수에 세요. 그 대화를 열어 보면 읽음이 돼요. 상태 점검 같은 조용한 글은 행이 되지 않아요.
- 이 화면에 대화 기록 모양(말풍선, 입력창, 날짜 구분)을 두지 마세요. 이유: 알림은 훑어서 처리하는 목록이에요.
- 점이나 태그에 파랑을 쓰지 마세요(가격 변경도 회색). 이유: 파랑은 진행 중 전용이에요.
- 읽은 새 소식을 제자리에 두지 마세요(지난 알림으로 옮겨요). 처리할 것만 읽어도 자리에 남아요.

## 답장 대기 (모니터링 > 답장 대기)

**언제**: 앱마다 흩어진 답장(보내기 전 확인, 못 보낸 것, 오늘 보낸 것)을 한 목록에서 처리할 때. 새 화면이 아니라 모니터링의 한 항목(`MON.sel === "replies"`)이고, 모양은 시안의 `#queue`예요(`site/prototype/s-queue.js`).
**생김새**
- 머리는 스크롤 영역 맨 위에 붙어요(`.rq-hd2`, sticky): 탭 `.nsc-f`(전체 · 답 필요 · 실패 · 보낸 것, 개수는 `.n`, 실패 개수는 `--err`, 전체는 개수 없음), `빠른 처리`(tonal sm)는 넓은 화면(640px부터)에서 탭과 같은 줄의 오른쪽 끝, 폰에서는 탭 아래 줄의 오른쪽 끝이에요(폰은 탭 개수에 따라 자리가 바뀌지 않게 줄을 나눠요). 개수는 탭에서만 말하고 이 줄과 구역 제목(`실패`·`답 필요`·`보낸 것`)에는 되풀이하지 않아요. 이 줄은 전체·답 필요 탭에서 답 필요가 `TR.min` 이상일 때만 나오고, 보낸 것 탭은 `오늘 보낸 답장 N건`이에요. 앱 필터(`RQ.app`; 탭 줄 오른쪽 끝의 `앱` 선택 단추, 폰은 탭 아래 짧은 줄)은 앱 행의 `답장 대기` 버튼으로 들어왔을 때만 나와요.
- 목록은 전체 탭에서 `실패 → 답 필요 → 보낸 것` 묶음(`.sec` + `N건`), 다른 탭은 그 묶음만. 행은 알림 행(`.nsc-r`)과 같아요: 상태 점(답 필요 주황, 실패 빨강, 보냄 초록), 받는 사람 `.hd`, 오른쪽 시각 `.t`, 아랫줄 `앱 · 무엇`과 멈춘 이유 `.tag`(실패는 `.tag.err`). 값이 없으면 자리도 없어요(원칙 13).
- 멈춘 이유는 실제 기록만 한 줄로, 있는 첫 번째: 실패는 `failed.why`, 답 필요는 `stops[ref]`(자동 규칙이 안 보낸 까닭) → `draft.warning` → `recipientWarning` → `draft.decide` 첫 줄 → 댓글 메모(`확인:` 접두 없이). 기록이 없으면 태그도 없어요. 보낸 것은 `how`로 `확인 후 발송` · `자동 발송` · `다시 보냄`.
- 같은 앱·같은 이유로 못 보낸 것이 2건 이상이면 한 행 `{앱} N건을 못 보냈어요`로 접어요: 이유가 아랫줄, 오른쪽에 tonal `모두 다시 보내기`, 맨 끝 ▾(`aria-expanded`)로 아래에 낱개 행(`data-kid`)이 펼쳐져요. 아니면 낱개 행이에요.
- 행을 누르면 시트 하나(`fsOpen`, 라벨 `답장 확인`)가 열려요: 맨 위 이유 한 줄(`.rq-why`), 그 아래 기존 답장 카드(`rqCardOf`, 10-reply-card.js). 실패는 `다시 보내기` · `보내지 않기`, 보낸 것은 읽기 전용 `보냈어요`예요. 항목이 목록에서 빠지면 시트도 닫혀요.
- 채팅: 한 대화에 보내기 확인 카드가 2건 이상 기다리면 독 카드와 포인터 없이 입력창 맨 위에 한 줄(`#qline`: 점, `답장 초안 N건 기다려요 · 확인하기`)만 보여요. N은 이 화면의 답 필요 값이고 누르면 이 화면이 열려요. 초안 여러 건이 든 메시지는 기다리는 동안 첫 문단만 보여요(`.q-fold`). 1건이면 지금의 카드예요.
**숫자는 하나**: `rqWaiting()`(답 필요 + 실패, 다른 컴퓨터 것 포함). #nav-mon, 탭 개수, 목록 행, 홈의 `답장 대기 N건` 행이 모두 이 값을 읽어요. 모니터·앱 오류는 이 숫자에 넣지 않고, 숫자가 0일 때만 작은 점(`nub`, `확인할 것 N개`)으로 보여요.
**하지 말 것**
- 모두 다시 보내기로 이미 승인한 실패 말고는 아무것도 보내지 마세요(`/api/approvals`에 고른 답을 보내지 않아요). 이유: 승인은 한 번만 해요.
- 시안의 예시 이유(`D.queueWhy`)나 지어낸 이유를 쓰지 마세요. 이유: 기록이 없으면 태그도 없어요.
- 목록을 카드 더미로 그리지 마세요. 이유: 처리할 것을 한눈에 훑으려는 화면이에요.

## 두 값 설정

**언제**: 설정 행의 값이 딱 두 개일 때(예: 한도에 걸리면 물어보기 = 기다리기 / 자동 전환).
**생김새**
- 켜기·끄기면 스위치(`.hs-sw`, `role="switch"`) 하나예요.
- 그 밖의 두 값은 `rowToggle()`가 만드는 작은 알약 하나(`.chip.tgl`, 28px)예요. 지금 값만 보여 주고, 누르거나 Enter·Space를 치면 다른 값으로 바뀌어요. 알약 오른쪽 작은 ⇄ 표시가 눌러서 바꾸는 컨트롤이라는 걸 알려 줘요.
- 행 아래 설명줄(`.sup`)은 지금 값에 맞춰 바뀌어요. 아직 정하지 않았으면 알약에 "정하기"가 나오고, 처음 누르면 첫 값이 돼요.
- 값이 세 개 이상일 때만 펼친 선택지(`.seg`)나 메뉴를 써요.
**하지 말 것**
- 두 값을 버튼 두 개로 나란히 펼치지 마세요. 이유: 원칙 3, 행 오른쪽 칸 하나에 컨트롤 하나예요.


## 같은 종류 설정 묶기

**언제**: 같은 종류의 설정 대상이 셋 이상 나란히 있을 때(메신저 네 개).
- 설정 목록에는 한 행만 두고, 오른쪽에 상태를 한 줄로 요약해요("Discord 연결됨", "Discord 외 1개 연결됨", "설정 안 됨").
- 누르면 그 종류의 목록 화면이 열리고, 각 행은 지금의 개별 화면으로 가요. 옛 주소와 명령 팔레트 항목은 새 자리로 이어져요.
- 한 대상에 딸린 설정(구독 계정, 자동 전환, 한도에 걸렸을 때, 전환 규칙)은 따로 화면을 만들지 않고 그 대상의 섹션 안에 둬요. 설정 > 계정 한 화면에 공급자마다 섹션을 두고, 로그인·계정·사용량·자동 전환을 그 안에서 관리해요. 계정이 있는 카드는 남은 한도 줄, 작은 이름 `계정`과 계정 행들(끝에 `+ 계정 추가`), 작은 이름 `한도에 걸리면`과 그 행들 순서이고, 휴지통은 없어요. 로그인이 풀린 계정에만 `다시 로그인`을 두고, 삭제는 계정 행을 눌러 연 창에서 해요.
- 섹션에 딸린 추가 동작은 섹션 제목 오른쪽의 작은 tonal 버튼(`.sec-act > .btn.tonal.sm`)이에요.

## 점 배지·전환 표시

안 읽은 숫자(`.nb`)는 개수 배지예요. 라이트에서는 파란 바탕(`--accent`)에 흰 숫자, 다크에서는 주황 바탕(`--unreplied`)이고, 앱·프로젝트 행, 홈 카드, 메일·댓글·카카오형 목록 행 어디서나 같은 캡슐(11px, 높이 18px)이에요. 숫자가 붙은 미답장(`미답장 N`, `.nb.unreplied`)은 옅은 주황 바탕의 같은 캡슐이고, 앱 머리글·홈 행과 머리·댓글 행에서도 똑같이 보여요. 개수는 배지, 상태는 점과 글자예요: 숫자 없이 한 건이 밀렸다는 뜻의 미답장(`.tag.unreplied`)은 점 + 글자로 둬요. 확인 필요(`.warn`), 초안 수는 자기 색을 그대로 써요. 기록 행과 소식 행의 안 읽음 점(`.hr .dot.un`, `.fr.un`)도 같은 색을 따라요.

**언제**: 탭·메뉴·이름에 "새로 생긴 것이 있다"만 알릴 때(개수는 숫자 배지).
**생김새**
- 점(`.nub`, PC 6px, 폰 탭 8px)은 글자의 오른쪽 아래 모서리에 붙어요. 폰 페이지 제목의 다른 컴퓨터 점(`.pdot`)은 제목 옆 펼침 화살표의 오른쪽 위에 붙어요. 폰 하단 탭의 홈 아이콘에도 같은 값에서 나온 다른 컴퓨터 점(`#nav-pc`)이 오른쪽 위에 붙고(8px, 파랑, 답 필요가 있으면 `--warn`), 대화 화면을 포함한 모든 탭에서 보여요. 넓은 화면에서는 이 점을 숨겨요. 폰 하단 탭은 아이콘 오른쪽 위에 붙어요. 탭 점(`.ni .nub.att`) 색은 라이트에서 파랑(`--accent`), 다크에서 옆 숫자(`.nnb`)와 같은 주황(`--warn`)이에요.
- PC 사이드바 탭은 새로 볼 것이 있으면 글자 바로 뒤에 6px 점 하나만 보여 줘요. 개수는 쓰지 않고, 폰 하단 탭과 같은 값에서 나와 함께 사라져요. 없으면 자리도 남기지 않아요.
- PC 사이드바는 접을 수 있어요(사이드바와 메인 단의 경계, 페이지 제목 높이의 얇은 화살표. 자리를 차지하지 않고 열린 상태는 ‹, 접힌 상태는 ›, ⌘\\ / Ctrl+\\). 접으면 60px 아이콘 줄이 되고, 글자·브랜드 이름·⌄는 숨어요. 사용량 줄은 같은 값·같은 경고색의 작은 원형 링과 그 안의 숫자로 바뀌고, 누르면 사용량이 열려요. 이름은 `title`과 `aria-label`에 남고, 탭 점은 아이콘 오른쪽 아래, 다른 컴퓨터 점은 로고 오른쪽 아래에 같은 6px·같은 색으로 붙어요. 접은 상태는 `dotz-side`에 저장되고 첫 그림 전에 적용돼요.
- 모니터링 탭: 답장 대기(답 필요 + 실패)가 있으면 그 숫자, 없는데 모니터·앱의 실패나 연결 끊김이 있으면 `확인할 것 N개` 점, 그것도 없는데 안 읽은 감시 소식이나 앱의 안 읽은 것이 있으면 `새 소식` 점이에요. 읽으면 사라져요.
- 누르면 다른 컴퓨터로 바꾸는 이름(PC 브랜드, 폰 페이지 제목)에는 이름 뒤에 작은 ⌄(`--fg-3`)가 붙어요. 컴퓨터가 하나뿐이면 없고 자리도 남기지 않아요.
- PC는 브랜드 한 줄이 컴퓨터 전환을 겸해요(로고, 봇 이름, ⌄). 지금 컴퓨터는 열린 목록의 체크로 알아요. 다른 컴퓨터에 안 읽은 것이 있으면 ⌄ 오른쪽 아래에 점이 붙어요(로고의 파란 점과 떨어져 있도록).
- 컴퓨터를 바꾸면 홈은 그 컴퓨터에서 마지막으로 본 모습으로 바로 떠요(이 기기에 남긴 상태와 답변 필요, 일주일 넘게 안 쓴 기록은 안 써요). 서버 답이 오는 대로 같은 자리가 새 값으로 바뀌고, 로딩 표시는 따로 없어요. 접근이 끊긴 기기에서는 대화 기록과 함께 지워져요.
- 새 버전 알림 바는 업데이트가 끝나면 "마쳤어요"를 잠깐(2.4초) 보여 주고 저절로 사라져요(페이드와 높이 접힘 250ms, 동작 줄이기 설정이면 바로). 그 전에는 그대로 있어요.

## 카드 (결과·확인·요약)

**언제**: 결과(끝난 일과 파일), 확인(내가 눌러야 하는 초안·결정), 요약(숫자와 상태) 하나를 한 덩어리로 보일 때.
**생김새**
- `.card`: `--r-card` 18px, 안 여백 20px(글자는 가장자리에서 12px 이상), 바탕 `--card`, 테두리·그림자 없음. 카드 사이 12px(`.col`).
- 제목 `.ch h3` 16/22 600, 큰 값 `.big` 20/28 700(카드당 하나), 본문 14/22, 메타 12/16 `--fg-3`. 제목과 부제 사이 4~6px.
- 버튼 줄은 `.cf`(위 12px, 간격 8px, 작은 단계 32px). 맨 아래 여백도 위와 같은 20px. 확인 카드만 채운 버튼 하나를 가져요.
- 결과 카드는 완료 표시 옆에 파일·링크 칩을 붙여요(원칙 7). 상태가 바뀌면 `motionSwap`으로 제자리에서 바꿔요. 같은 말을 머리·행·꼬리에 되풀이하지 않아요.
**하지 말 것**
- 카드 안에 카드를 넣지 마세요. 이유: 회색 단계(`--layer`)로 충분하고 겹치면 시선이 흩어져요.
- 색 띠나 그림자를 두르지 마세요. 이유: 원칙 9, 그림자는 떠 있는 것(메뉴·창)만 써요. 주인공 카드를 강조 테두리로 둘러싸지도 마세요(테두리는 입력 포커스만).
- 상태가 바뀔 때 새 카드를 아래에 추가하지 마세요. 이유: 원칙 6, 내용이 밀려요.
- 버튼 줄을 입력칸이나 선에 붙이지 마세요. 이유: 8px 안쪽이면 닿아 보여요.

## 홈 상태 카드 (요약 띠 + 카드)

**언제**: 홈의 "상태" 칸. 한눈에 볼 숫자(요약 띠)와 그 아래 종류별 카드. 카드는 `.board`(`makeBoard(..., { px: true })`)의 한 칸이고 끌기·크기 바꾸기·카드 추가·배치 초기화는 그대로예요.
**공통**
- 높이는 내용이 정해요(`fit`). 같은 줄 카드끼리 높이를 맞추지 않아요: 두 장이 한 줄을 쓰면 줄은 키 큰 쪽만큼이지만, 빈 카드(`진행 중인 작업이 없어요`)는 옆 카드 높이로 늘어나지 않고 제 내용만큼이에요(형 결정 2026-11-09). 가로만 12칸 중 3~12칸으로 바꿀 수 있고, 처음엔 4칸이라 카드 여섯 장이 두 줄을 꽉 채워요. 위쪽 카드가 짧으면 아래 카드가 같은 칸 안에서 올라와 붙어요.
- 머리 `.ch`는 모든 카드가 같아요: [상태 점] 제목(`h3`) · 개수나 한마디(`.hc-n` 13/18 `--fg-3`, 글자만, 칩 없음) · ⋯ 메뉴(`.ib` 24). 태그(`.tag`)·큰 숫자(`.big`)·조각난 칩은 머리에 쓰지 않아요. 이유: 카드마다 다르게 생기면 읽는 법을 매번 다시 배워요(원칙 2·9).
- 머리의 개수(`.hc-n`)는 그 카드 목록에 그려진 줄 수예요. 알림 카드는 읽지 않은 알림 줄 수(`hcFyi`)이고, 목록에 없는 알림은 세지 않아요.
- 목록이 있는 카드(답변 필요, 답장 대기, 할일, 지금 진행 중, 대기 중, 최근 끝난 작업, 알림, 작업내역, 모니터링, 사용량, 컨텍스트, 공급자, 내가 만든 목록·항목별 값 카드)는 규칙 하나를 같이 써요(`data-cap`, `capLists`, `.list-cap`): 7줄부터 6번째 줄까지의 높이로 고정하고 카드 안에서만 스크롤해요(스크롤바 없음, 머리 고정). 더 있으면 마지막 줄이 옅어지고 끝까지 내리면 사라져요. 새로고침해도 스크롤 위치와 포커스가 그대로고, 옆 카드 높이는 안 변해요. 6줄 이하는 그대로예요. 먼저 3줄·5줄로 자르지 않아요.
- 강조색은 상태 점 하나뿐이에요(주황 `warn`·`att` = 내가 할 일, 빨강 `err` = 실패, 초록 `ok`, 파랑 `pri` = 진행 중). 카드 바탕·테두리·막대에는 색을 칠하지 않아요. 막대는 `--fg-2` 한 색이고, 주의가 필요한 줄은 이름 앞 점으로만 알려요.
- 내용이 없으면 접어요: 머리 아래 8px에 `.hc-none` 한 줄로 이유("없어요", "새 알림이 없어요")를 쓰고, 카드 안쪽 여백은 사방 20px예요. 본문 칸·머리의 본문 간격·빈 줄을 남기지 않아요(원칙 13). 지금 진행 중, 답변 필요까지 모든 카드가 같고, 불러오는 중이거나 불러오지 못했을 때도 같은 한 줄이에요.
- 일의 상태는 네 묶음이고, 한 항목은 언제나 한 곳에만 있어요. 이유: 같은 일이 두 곳에 보이면 몇 개가 도는지 셀 수 없어요. 판정은 `renderHomeNow`(`web/js/08-home.js`) 한 곳이에요.

| 묶음 | 들어가는 것 | 줄 | 나가는 때 |
|---|---|---|---|
| 할일 | 받았지만 시작 전: 한도에 걸린 맡긴 작업·세션, 한도 리셋까지 미룬 일(`/api/state` `waitlist`, `hub/waitlist.ts`) | 오래된 순서, 순번과 제목. 미룬 일은 재개 시각 | 시작하면 저절로 |
| 지금 진행 중 | 정말 돌고 있는 것(`homeRunning`)과 형의 답을 기다리는 세션(맨 위, `답을 기다림`). 세션 행은 `프로젝트 · 제목`이고 채팅 목록 `진행 중`(땅콩·작업내역 바로 아래)과 같은 목록(`sessionsNow`)이에요 | 하는 일, 시간 | 끝나거나 멈추면 |
| 대기 중 | 시작했다가 멈춘 것: 형이 멈춤, 막힘(오류, 멈춘 맡긴 작업, 남은 일), 사용량 한도 | 멈춘 이유 | 다시 돌면 |
| 최근 끝난 작업 | 한 시간 안에 끝난 맡긴 작업과 세션 | 끝남·실패 | 한 시간 뒤 |

- 할일 카드는 비어 있어도 늘 있고(`.hc-none` 한 줄), 끌어도 격자 맨 앞에 고정이에요(`pin`). 끝낸 일이 기다리는 듯 보이면 안 되니 끝난 세션의 단어는 대기가 아니라 끝남이에요. 시작 전인 항목은 회색 `순서 대기`라 사이드바 점, 인사의 세션 수, 프로젝트의 진행 판정 어디서도 도는 것으로 세지 않아요. 게이트웨이는 모델 없이 제 상태만 읽어, 웹이 열려 있을 때 5초마다 비교하고 바뀌면 스트림 `{ kind: "waitlist" }`로 알려요.
- 끝난 줄(최근 끝난 작업, 작업내역)은 결과 칩 대신 줄 오른쪽에 개수만 보여요: 클립 아이콘 + `결과 N`(`.hrx-n`, 12/16 `--fg-2`, 줄 높이는 그대로). 누르면 그 줄 아래에 같은 결과 칩이 펼쳐지고(한 번에 한 줄), 다시 누르거나 Esc면 접혀요. 버튼이라 키보드로도 열고 `aria-expanded`로 상태를 알려요. 결과가 없는 줄은 아무것도 안 붙어요. 이유: 칩을 다 펼치면 끝난 줄이 세 배로 길어져 홈이 한눈에 안 들어와요(형 결정 2026-11-09). 프로젝트 화면의 완료·결과 줄은 칩을 그대로 보여요.
- 카드 전체를 누르면 그 화면으로 가고, 줄을 누르면 그 항목으로 가요. 줄 안 ⋯는 그 항목의 동작이에요. 굵은 글자는 카드당 제목 하나(진한 글자 중복 규칙).
**종류별**
- 요약 띠(어시스턴트, `id=main`, 12칸): 머리에 상태 점 + 이름 + 상태 한마디 + ⋯. 아래에 `.hsum` 칸 — 칸마다 위에 이름(12/16 `--fg-3`), 아래에 값(20/28 500). 모델 · 추론 강도 · 5시간 남음 % · 7일 남음 % · 안 읽은 알림 개수. 남은 한도가 30% 이하면 값 앞에 주황 점. 폴백 중이면 한 줄(`.sup`)로, 서브에이전트가 돌면 점 + 한 줄로 아래에 붙여요. 데이터가 아직 없는 칸은 만들지 않아요.
- 알림: 머리 개수 = 안 읽은 알림. 본문은 최신순 목록(점·제목·시각). 화면이 받아 둔 최근 300건 안에서 그려요. 없으면 접어요.
- 작업내역: 본문은 최신순 목록(결과 포함). 점과 제목은 작업내역 대화의 행과 같은 규칙으로 그려요(상태 점, 표식과 주장 단어 없는 첫 문장). 화면이 받아 둔 최근 300건 안에서 그려요. 없으면 접어요.
- 모니터링: 본문은 항목 목록(점 · 이름 / 마지막 확인·상태·다음 확인 12px), 7개부터 "더 보기 · N개"(6줄 뒤의 개수, 누르면 모니터링). 머리 개수는 실패가 있을 때만 빨간 점 + "실패 N". 없으면 접어요.
- 컨텍스트: 줄마다 이름 + 퍼센트(14/20, 오른쪽) 아래에 막대(4px). 80% 이상인 줄은 이름 앞 주황 점. 머리 개수 = 줄 수. 없으면 접어요.
- 사용량: 한도마다 이름 + "N% 남음" + 막대. 남은 비율이 20% 이하이거나 한도에 닿은 줄은 이름 앞 주황 점. 없으면 접어요.
- 사용량 화면의 Codex 카드: 한도 줄 아래 "리셋권 N개" 줄(가장 빠른 만료일)과 `사용` 버튼. 리셋권이 없거나 한도에 걸린 곳이 없으면 버튼이 꺼져요. 누르면 다시 채울 한도와 남을 개수를 보여 주는 확인 단계를 거쳐야만 써요.
- 사용량 화면의 Claude 카드: 같은 "리셋권 N개" 줄, 아래에 종류별 개수(주간 1 · Fable 3)와 가장 빠른 만료일. `사용`은 지금 쓸 수 있는 리셋권이 없거나 이 컴퓨터에서 계정의 조직을 모르면 꺼져요. 누르면 어느 리셋권을 쓰는지와 되돌릴 수 없다는 확인 단계를 거쳐요. 토큰이 만료된 계정은 줄이 없어요.
- 공급자: 줄마다 점(초록 로그인됨, 주황 로그인 필요) + 이름 + 계정. 목록만, 막대 없음. 없으면 접어요.
- 묶음을 푼 개별 카드(컨텍스트·사용량·공급자)는 같은 머리에 값을 `.hc-n`으로 써요.
**하지 말 것**
- 카드 높이를 칸 수로 고정하지 마세요. 이유: 내용이 적은 카드 아래가 비고 많은 카드는 잘려요.
- 비었다고 "없어요" 한 줄을 본문 칸에 따로 두지 마세요. 이유: 접어서 머리에 쓰면 한 줄이에요.
- 어시스턴트 카드만 살구색으로 칠하거나 "확인 필요"·"작업 중" 태그를 달지 마세요. 이유: 점이 같은 말을 이미 해요(원칙 9).

## 설정 행 (제목·설명·오른쪽 컨트롤)

**언제**: 설정 하나(켜기·끄기, 값 고르기, 값 쓰기, 한 번 누르기)를 보여 줄 때.
**생김새**
- `.li` 그대로. 왼쪽 `.tx` = `.hd` 제목(15/22 500) + `.sup` 한 줄 설명(12/16 `--fg-2`, 제목과 4px), 오른쪽에 컨트롤 자리 `.li-end` **하나**. 행 안 세로 가운데(`align-items: center`)는 `.li`가 맞춰요.
- 컨트롤은 **행 안(28px)** 이나 **작은(32px)** 단계만: `.btn.inrow`, 스위치 `.hs-sw`(36x20), 고르기·입력 `.sel`/`.fi`(`.li-end` 안에서 너비 160px, 높이 32px, 터치 화면 40px), 값 글씨. 컨트롤은 내용만큼만 차지하고 오른쪽 끝(가장자리 16px 안쪽)에 서요.
- 최소 행 높이 44px, 안 여백 8px 16px. 설명이 길면 `.tx`가 줄을 바꾸고 컨트롤은 가운데에 그대로 있어요. 같은 목록 모든 행의 컨트롤은 같은 오른쪽 x에 서요.
- 목록 하나에 "추가"가 필요하면 그 목록 위 구역 제목 줄에 둬요: `.sec.sec-act` 안 오른쪽 `.btn.tonal.sm` 또는 `.btn.text.sm`(32px, 제목과 8px). 추가 입력이 필요하면 눌렀을 때 그 자리 행이 입력칸으로 바뀌어요(`motionSwap`).
- 빼기는 행 오른쪽 `.ib`(28px, 터치 36px) 하나.
- 진단 행: 설정 > 표시의 "입력 진단" 스위치(또는 `?kbdiag=1`)가 켜지면 입력칸에서 나올 때마다 기록해요(칸 이름·직전 이벤트·호출 위치만, 쓴 글은 없음). 켜진 동안만 "진단 기록"(복사)과 "진단 기록 지우기" 두 행이 생겨요(행마다 컨트롤 하나)(web/js/34-input-diag.js). 터치 화면(폰)에서는 스위치와 상관없이, 주인이 누르거나 화면을 옮기지 않았는데 입력칸이 포커스를 잃거나 화면에서 사라지면 그 한 건(칸 이름·직전 이벤트·호출 위치·화면 높이 전후·앱 빌드, 쓴 글 없음)을 게이트웨이로 보내요(분당 3건까지). 받은 기록은 데이터 폴더의 `input-diag.jsonl`에 최근 200건만 남아요(hub/input-diag.ts, `POST /api/input-diag`). 데스크톱에서는 보내지 않아요.
**하지 말 것**
- 목록 아래에 가로로 꽉 찬 버튼이나 기본 크기(36px) 버튼을 띄우지 마세요. 이유: 행보다 커져서 눈에 제일 먼저 들어오고, 어느 목록의 버튼인지 흐려져요(디스코드 "추가"가 그랬어요).
- 오른쪽에 컨트롤을 둘 이상 두지 마세요. 이유: 원칙 1, 한 행에 할 일이 하나여야 해요. 둘째 동작은 행을 눌러 여는 시트로 옮겨요.
- 행 안 버튼을 `.li-end` 밖에 두지 마세요. 이유: 세로 가운데와 오른쪽 끝이 화면마다 달라져요.
- `.li-end`를 `flex: 1`로 늘려 컨트롤을 한쪽으로 몰지 마세요. 이유: 한쪽만 빈 컨트롤은 어긋나 보여요.
- 설명을 두 줄 넘게 쓰지 마세요. 이유: 원칙 4, 더 필요하면 "자세히"로 접어요.
- 설명(`.sup`·`.note`·힌트)은 다음에 할 일을 알려 줄 때, 숫자나 한도일 때, 보안·비용 사실일 때, 되돌릴 수 없는 동작의 확인 문구일 때만 둬요. 그 밖에는 지우거나 한 줄로 줄여요.

## 시트·대화창

**언제**: 지금 화면을 떠나지 않고 한 가지를 확인하거나 입력받을 때(`.fs-card`), 옆에서 훑는 긴 내용(`.sheet`).
**생김새**
- 대화창 `.fs-card`: 너비 `min(560px, 100% - 48px)`, 모서리 20px, 바탕 `--card`(어두운 테마는 `--pop`), 그림자 `--float`, 뒤 `--scrim`. 높이 `min(86dvh, 820px)`를 넘으면 `.fs-body`만 스크롤.
- 머리 `.fs-hd` 안 여백 16px 8px 12px 24px, 제목 `.fs-t` 20/28 700. 본문 `.fs-body` 여백 4px 24px 16px. 아래 `.fs-ft` 여백 12px 16px 16px(맨 아래도 위와 같은 여백), 버튼 간격 8px, 오른쪽 정렬. 본문 첫 줄은 머리에서 16px 이상.
- 버튼은 기본 단계(36px) 채운 것 하나 + 다른 건 tonal/text. 나타날 때 `motionIn`(8px 떠오름, 220ms), 닫을 때 `await motionOut` 뒤 제거. 열린 자리에서 크기를 바꾸지 않아요.
- 확인 상자 `dialog({ confirm: true })`, `ask()`: 제목 하나, 한두 문장, 버튼 둘(취소 + 할 일)만 있는 짧은 확인이에요. PC는 너비 `min(360px, 100vw - 24px)`의 작은 상자로 방금 누른 자리 바로 아래(자리가 없으면 위, 화면 안으로 12px 띄움)에 뜨고, 방금 누른 게 없으면 가운데예요(여백 20px, 모서리 20px), 폰(639px 이하)은 아래에서 올라오는 낮은 시트(위 모서리 20px, 버튼은 반씩 나눠 44px)예요. 전체 화면(`.fs-card`)은 편집하거나 긴 내용을 볼 때만 써요. 시트나 상자가 열려 있는 동안 묻는 확인은 새 창을 열지 않고 그 안의 내용을 바꿔 보여 주고(`motionSwap`), 답하면 원래 내용으로 돌아와요.
- 중간 시트 `.fs-card.mid`: 입력 하나와 짧은 목록(앱 관리처럼). PC는 가운데 상자, 폰은 아래에서 올라오는 시트(위 모서리 20px, 높이는 내용만큼, 최대 86dvh)예요. `dialog({ mid: true })`로 여는 창(기기 이름, 이 컴퓨터 이름, 공급자 로그인·추가, API 키, 앱 설정, 남겨 둔 세션 알림)도 같은 모양이에요. 칸이 둘 이하이거나 글만 있는 창이 쓰고, 긴 편집 창은 화면 전체로 둬요. ✕가 있는 창에는 하는 일이 없는 "닫기" 단추를 따로 두지 않아요.
- 메일 답장 보내기 시트는 중간 시트 `.fs-card.mid.rq-sheet`예요: 머리는 `답장 확인`(뒤에 기다리는 카드가 더 있으면 옅은 글 `· 남은 N건`)과 닫기 ✕ 하나뿐이고 `무시`는 없어요. 본문은 답장 카드와 같은 굵은 제목, 본문, 접힌 받는이 한 줄이고, 받는이가 비었거나 주소가 틀리면 처음부터 펼쳐져요. 단추는 아래 `.fs-ft`에만 두고 폰에서 모두 44x44 이상이에요.

## 버튼

**언제**: 누르면 바로 일이 일어날 때. 이동은 링크나 행, 아이콘만 필요하면 `.ib`.
**생김새** 크기는 딱 세 단계, 강조 규칙은 하나.

| 단계 | 클래스 | 높이 | 안 여백 | 글자 | 쓰는 곳 |
|---|---|---|---|---|---|
| 기본 | `.btn` (`--btn-h`) | 36px | 0 16px | 14/20 600 | 화면·대화창의 주 동작 |
| 작은 | `.btn.sm` (`--btn-h-sm`) | 32px | 0 12px | 13/20 600 | 카드 아래 줄 `.cf`, 구역 제목 줄 |
| 행 안 | `.btn.inrow` (`--btn-h-row`) | 28px | 0 12px | 13/20 600 | 목록·설정 행 오른쪽 `.li-end` |

- 공통: 모서리 `--r-ctl` 10px(알약 아님), 아이콘 16px과 글자 사이 6px, 한 줄(`nowrap`), 내용만큼만 차지. 글자는 상자 안에서 위아래 가운데. 터치 화면은 높이를 늘리지 않고 누르는 영역만 44px(`--btn-hit`)로 넓혀요(행 안은 28px 상자 + `::after` 위아래 6px = 40px). 앱바 단추(아이콘 버튼 `.ib`, 사용량 줄 `.ustrip`, 연결 끊김 알약 `.conn`)도 같아서, 폰에서는 `::after`가 보이는 상자 가운데에 44px로 깔리고(뒤로 가기는 화면 가장자리라 안쪽으로 넓혀요) 이웃한 아이콘 버튼은 가운데끼리 44px 간격이에요: 검색·알림, 메일·카카오 제목줄의 대화·⋯ 단추. 사용량 줄은 알림 단추와 2px 떨어져요. 화면 본문의 단추·칩·편집 글줄도 폰에서 같은 방식이라 보이는 크기는 그대로 두고 `::after`로 44px(행 안 40px)를 채워요. 가로로 밀리는 칩 줄은 영역이 잘리지 않게 위아래 안쪽 여백으로 자리를 만들고 같은 만큼 바깥 여백을 빼서 줄 높이를 지켜요. 열린 메일 막대(`.mtop`)는 맨 앞·맨 끝 단추의 영역을 막대 안쪽으로 붙여 막대가 옆으로 밀리지 않게 해요. 입력 칸(`input`/`textarea`)은 `::after`를 못 쓰니 칸 높이 토큰을 따르고, 가운데가 잘리는 분할 단추(`.seg`)와 받는 사람 칩은 이웃 영역을 덮어서 그대로 둬요.
- 강조: 한 화면(또는 한 카드)에 채운 `.btn`(`--accent`) **하나**. 나머지는 `.tonal`(`--layer`) 또는 `.text`(투명, `--fg-2`). 위험은 `.danger`(글자만 `--err`), 확정 삭제만 `.danger.fill`.
- 올리면 tonal은 `--hover`, 채운 것은 같은 색 `opacity .85`(회색으로 바뀌지 않음). 눌릴 수 없으면 `.4`. 눌렀을 때 라벨이 바뀌어도(보내기 → 보냈어요) 버튼 자리와 너비는 가장 긴 라벨에 맞춰 그대로예요.
**하지 말 것**
- 위 세 높이 말고 28·34·38 같은 값을 새로 만들지 마세요. 이유: 같은 화면에 비슷하지만 다른 버튼이 생겨요.
- 채운 버튼을 두 개 이상 두지 마세요. 이유: 원칙 1, 무엇이 주인공인지 사라져요.
- 가로 전체 너비로 늘리지 마세요(폰 시트 맨 아래 하나만 예외). 이유: 글자 수와 상관없이 커 보여요.

- 라벨을 두 줄로 쓰지 마세요. 이유: 높이가 깨져요. 동사 하나("추가", "저장")로 줄여요.

## 배지·점

**언제**: 종류나 상태를 한 단어로 알릴 때(`.tag`), 줄 앞에서 상태만 알릴 때(`.dot`).
**생김새**
- `.tag`: 높이 20px, 안 여백·바탕 없음, 11/16 500, 글자 `--fg-3`(메타 글자). 상태색 `.ok/.warn/.err/.unreplied`는 앞에 6px 색 점 + 그 색 글자 600, `.pri`는 파란 점 + `--fg-2` 글자(파란 글자는 흰 바탕에서 4.5:1이 안 돼요).
- `.dot`: 8px 원, 글자와 6px 이상 띄움, 행 안 여백 안쪽에. 색은 상태 규칙(파랑 진행·주황 내 차례·빨강 실패·초록 완료·회색 그 외). 진행 중 `.dot.pri`도 깜빡이지 않아요(색으로만 말해요). 이유: 목록에 진행 중인 행이 여럿이면 화면 전체가 숨 쉬어요.
- 한 줄에 둘까지. 글은 두세 글자 단어("진행 중", "새 버전"). 점·배지는 열이 아니라 아이콘 칸이나 글 앞에 붙어요.
- 세션·대화·맡긴 작업의 색은 한 곳에서 정해요: 대화와 세션은 `runStatus`(`web/js/41-runstate.js`, 단어와 색을 함께 돌려줘요), 맡긴 작업은 `workTone`(`web/js/06-subagents.js`). 행마다 다시 계산하지 마세요. 색은 혼자 말하지 않아요. 색마다 단어가 달라서 색을 못 봐도 뜻이 남아요.

| 색 | 뜻 | 쓰는 단어 |
|---|---|---|
| 파랑 `pri` | 돌거나 진행 중 | 작업 중, 시작 중, 진행 중, 이어서 처리 중 |
| 주황 `warn`(`att`는 같은 색의 옛 이름) | 형이 답해야 하거나 한도에 걸림 | 답을 기다려요, 한도 걸림, 멈춤(맡긴 작업), 확인 필요 |
| 빨강 `err` | 실패했고 아무도 안 받음 | 오류 |
| 초록 `ok` | 잘 끝남(맡긴 작업, 대화 위 상태 줄) | 완료, 끝났어요 |
| 회색(없음) | 쉬거나 꺼졌거나 처리됨, 아직 시작 전 | 대기, 순서 대기, 멈춤(세션), 끝남, 종료됨, 중단됨, 실패(이어서 처리함) |

맡긴 작업의 실패는 에이전트가 이어받으므로 파랑이고, 이어받은 뒤에는 회색이에요. 끝나고 쉬는 세션은 초록이 아니라 회색이에요. 초록이면 쉬는 세션이 전부 초록이 돼요. 홈 인사 문구는 `homeRunning`(`web/js/08-home.js`)을 읽어요: 지금 진행 중에 돌아가는 줄이 있으면 일하는 중, 형의 답만 남았으면 답을 기다려요, 정말 아무것도 없을 때만 쉬는 중이에요. 다른 컴퓨터의 일은 홈에 없으니 세지 않아요.
**하지 말 것**
- 상태색을 꾸밈에 쓰지 마세요. 이유: `web/DESIGN.md` 상태 색 규칙, 색은 상태 하나를 뜻해요.
- 배지를 누르는 버튼처럼 만들지 마세요. 이유: 20px는 누르기엔 작아요. 누를 건 `.btn.inrow`.
- 점·배지를 글자나 가장자리에 걸치게 두지 마세요. 이유: 안쪽 여백 안에 완전히 들어와야 잘리지 않아요.
- 개수는 배지가 아니라 숫자(`rollCount`)로 보이세요.

**언제**: 홈 카드를 만들거나 고칠 때. 대화상자가 아니라 화면이에요(`#cardform`, 수정은 `#cardform/<id>`, `web/custom.js` `cardForm`). 회색 바탕이라 칸은 `--card`로 채워요.
**생김새**
- 1100px 이상은 폼 왼쪽, 미리보기 오른쪽(380px, 위에 붙음). 그 아래는 미리보기가 위에 붙어요. 칸 높이는 이 폼만 44px.
- 미리보기는 홈과 같은 `cardNode`로 그려요. `inert`라서 누를 수 없고, 입력은 한 프레임에 한 번만 다시 그려요. 명령 실행이면 "저장하면 명령을 실행해 결과를 그려요" 한 줄이에요. 빈 값은 고른 보기 모양을 `--fg-3`로 보여 줘요.
- 순서는 제목, 보기(썸네일 라디오, 고른 쪽은 채움), 내용(오른쪽에 내용 출처), 더 보기(설명, 링크, 동작, 아이디, 요약에 "N개 채움"). 더 보기 안의 칸에 오류가 나면 저절로 열고 그 칸에 포커스해요.

## 입력창

**언제**: 글자나 숫자를 한 줄로 받을 때(`.fi`), 목록에서 하나를 고를 때(`.sel`). 긴 글은 composer/textarea.
**생김새**
- `.fi`/`.sel`: 높이 36px(터치 40px, 글자 16px — 확대 방지), 안 여백 0 12px, 모서리 `--r-ctl` 10px, 테두리 없음, 바탕 `--ff-fill`, 글자 13px(글자는 칸 안 위아래 가운데). 포커스는 안쪽 1.5px `--accent`(`--ff-ring`), 오류는 같은 굵기 `--err`(`aria-invalid="true"`). 이 칸을 쓰는 앱 전체의 입력칸(`.dc-note`, `.kk-rv`, `.tr-ta`, `.dr-edit`, `.au input` 등)이 같아요.
- 터치 화면에서는 입력칸, 입력창(컴포저), 긴 글칸, 고르기 어느 것도 글자가 16px 밑으로 내려가지 않아요. iOS가 16px 밑 칸을 누르면 화면을 확대하기 때문이에요. 입력창은 줄 높이 22px 그대로라 높이 36px도 같아요. 데스크톱 크기는 그대로예요.
- 대화 중이던 세션이 끝나도, 아직 글을 보낼 수 있는 세션(이어갈 수 있는 것)이면 입력창에 글이 있거나 커서가 있는 동안은 그 대화에 머물러요. 입력창을 벗어나 비면 그때 메인으로 가요. 목록에서 사라졌거나 완전히 끝났거나 지워진 프로젝트처럼 더는 보낼 수 없으면, 쓰던 글을 메인 입력창으로 옮기고(메인에 쓰던 글이 있으면 그 아래 줄에 붙여요) 커서도 그대로 둬요.
- `--ff-fill`은 칸이 놓인 면으로 정해요. 회색 바탕 위는 `--card`, 흰 면(`.card`, `.list`, 시트) 안은 `--layer`, 다크 대화상자(`--pop`) 안은 `--active`. 칸이 놓인 면과 같은 색이 되면 칸이 안 보이니, 새 흰 면을 만들면 `01-tokens.css`의 면 목록에 넣어요.
- 라벨은 위 `.lbl`(12/16 500 `--fg-2`, 위 16px 아래 6px) 또는 `.tf` 안 라벨(14/20 500 `--fg-2`, 칸과 8px). 도움말은 아래 `.sup`.
- 고르는 칸은 앱 전체에서 하나예요: `selectButton()`(`web/js/03-menu.js`, 라벨을 붙이면 `selectField()`)이 만드는 `.sel` 버튼과 공용 메뉴 `.menu`. 값은 `.value`로 읽어요. 네이티브 `<select>`는 쓰지 않아요(엔진마다 모양과 여백이 달라요). 오른쪽 화살표는 14px, 끝에서 12px이고 긴 글자는 말줄임으로 잘려요. 고른 항목은 체크와 500 굵기, 메뉴 항목은 30px(터치 44px)이에요. 메뉴는 대화창과 전체 화면 카드(`.fs-bd`) 위에 떠요.
- 바로 옆 칸과 나란히 쓰면 그 칸의 높이와 글자를 따라요(답장 고치기의 `.rq-edit .sel`은 입력칸처럼 40px, 16px).
- 설정 행 오른쪽 `.li-end` 안에서는 너비 160px, 높이 32px(터치 40px). 아래로 열리는 목록은 칸과 같은 너비로 맞추고 열린 동안 칸에 붙어 있어요.
- 모델 화면의 모델·추론 강도는 한 행에 나란히 서고(체인의 1번), 같은 높이(32px, 터치·좁은 화면 40px)에 위아래 8px 띄워 구분선에 닿지 않아요. 글자는 행 크기(`--fs-row`)예요. 폴백 단계도 한 행(번호, 모델, 짧은 요약, 상태, 켜짐·꺼짐, 손잡이)이고, 나머지 설정과 삭제는 행을 눌러 펼쳐요. 사용량은 상한의 80%부터 행에 나와요.
- 비밀 값은 `type=password`, `autocomplete="new-password"`.
**하지 말 것**
- 자리표시 글자를 라벨 대신 쓰지 마세요. 이유: 쓰기 시작하면 사라져요.
- 입력칸 높이를 화면마다 다르게 주지 마세요. 이유: 같은 줄에서 버튼과 어긋나요. 같은 줄의 버튼과는 같은 단계로 맞춰요.
- 입력칸 바로 아래에 버튼을 붙이지 마세요. 이유: 8px 안쪽이면 닿아 보여요.

### 컴포저 첨부 토큰

컴포저 글에는 `[이미지1]`, `[파일1]` 토큰이 파일을 넣은 자리에 그대로 들어가요(`web/js/15-attachments.js`).

- 입력은 끝까지 textarea예요. 한글 조합과 폰 키보드, 되돌리기를 브라우저에 맡기고, 위에 겹친 `.ta-tok`이 토큰 글자 바로 위에 불투명한 칩 `.atk-in`(14px 썸네일 + 라벨 12px)을 그려요. 칩 폭은 토큰 글자 폭과 같아요.
- 토큰을 지우면 파일이 빠지고, 트레이의 ×로 파일을 빼면 토큰도 지워져요. 되돌리기나 잘라낸 토큰 붙여넣기로 토큰이 돌아오면 파일도 돌아와요. 커서는 토큰 안에 머물지 않아요.
- 오래 걸리는 업로드는 칩에 원형 링과 `12MB / 340MB`를 보여 주고, 대화를 옮겨 다녀와도 이어져요(`web/js/15-upload.js`). 다 올라갈 때까지 보내기는 막혀 있고, 실패한 칩은 이유와 다시 올리기를 보여 줘요.
- 번호는 파일이 남아 있는 동안 바뀌지 않아요. 이미 쓴 글의 "이미지2"가 다른 파일을 가리키면 안 돼요. 보내면 1부터 다시 시작해요.
- 보낸 글은 토큰 자리를 그대로 지키고, `[attachment] 이미지1: 이름 (형식) 경로` 줄이 토큰과 파일을 이어요. 보낸 말풍선은 같은 칩을 그리고, 파일만 보낸 메시지는 말풍선 없이 썸네일만 둬요.
- 타임라인 그림은 `/api/file?thumb=1`(480px webp)이고, 원본은 라이트박스를 열 때만 받아요.

**라이트박스**(`dialog.lbox`): 바깥 누르기, Esc, 뒤로 가기로 닫혀요. 화면에 맞춰 보이고, 폰은 두 손가락 벌리기와 두 번 탭으로 확대해요. 여러 장이면 좌우 버튼, 방향키, 밀기로 넘겨요.

## 명령 팔레트 (⌘K)

- 한 일에 한 행이에요. `도구`(화면), `화면`(터미널·화면 공유·끝난 세션·테마), `명령` 순서로 놓아요.
- 같은 일을 하는 화면이 있는 명령(`/context`, `/quota`, `/providers`, `/terminal`)은 `/`를 쳤을 때만 나와요. 평소 검색에서는 화면 행 하나만 나오고, 옛 이름(공급자, quota)으로 찾아도 그 화면이 나와요.
- 값이 있어야 도는 명령의 행은 오른쪽에 명령 설명 대신 고를 것의 이름(`공급자 고르기`)을 적어요. 컴포저의 `/` 목록에서는 보내기 화살표와 Enter가 골라진 줄의 명령을 보내고(값이 필요한 명령은 칸에 넣어 줘요), `/` 한 글자만 있는 칸은 보내지지 않아요.
- 값이 있어야 도는 명령을 고르면 바로 실행하지 않고 고를 값을 행으로 보여 줘요. 미리 골라 두지 않아서 Enter를 한 번 더 눌러도 아무것도 실행되지 않아요.
- `/terminal`, `/screen`은 게이트웨이로 보내지 않고 이 페이지에서 열어요.
- 첫 화면부터 빈 곳이 없어요. 데이터가 오기 전에는 `불러오는 중…`을 보여 주고, 못 받으면 못 불러왔다고 말해요. 없는 주소는 홈으로, 없는 모니터링 항목은 모니터링 목록으로 가요.
- `hub/palette-routes-web.test.ts`가 412px과 1280px에서 모든 행과 옛 주소를 실제로 눌러 봐요. 행을 늘리면 이 테스트가 같이 봐요.
- 분할 칸의 배치(`배치 저장`, `배치: <이름>`, `배치 지우기: <이름>`)는 `화면` 묶음의 행이에요. 1100px 미만에서는 나오지 않고, `배치 저장`은 칸이 둘 이상일 때만 나와요.

## 분할 칸 (1100px 이상)

- 칸은 지금 대화 카드와 같은 카드예요(`--card`, `--r-card`, 그림자 없음). 칸 사이와 목록 단 사이는 `--sp-4`, 왼쪽 목록 단은 280px이에요.
- 활성 칸은 입력란 초점과 같은 `--ff-ring` 테두리 하나로만 구별해요. 비활성 칸을 흐리게 하거나 색을 바꾸지 않아요.
- 비활성 칸 머리줄은 대화 머리(`cv-hd-t` 16/22 600, `cv-hd-s` 12/16)와 같고, 오른쪽에 닫기(`.ib`)가 있어요. 입력창 자리는 진짜 입력창(`.sendrow`)과 같은 `--layer` 채움에 초안이나 안내 글을 보여 주고, 누르면 그 칸이 활성이 돼요.
- 전체 화면에 입력창이 있는 화면(대화, 카카오톡 방)은 칸 안에서도 입력창이 칸 바닥에 붙어 있어요. 내용을 끝까지 스크롤해도 가려지지 않아요. 카카오톡 방은 칸 안에서 답장 초안 카드가 요청 입력줄 위로 올라가 따로 스크롤돼요. 대화창은 세로의 40%를 지켜요. 전체 화면에 입력창이 없는 화면은 칸에서도 없어요(docs/split-panes.md 입력창).
- 열린 칸의 대상에서 온 알림은 토스트 대신 그 칸 머리줄 이름 앞의 점(`.dot` 기존 색)이에요. 그 칸을 활성으로 만들면 꺼져요.
- 끌기: 목록 행(왼쪽 메뉴 탭은 아니에요)을 6px 움직이면 제목 고스트(`--card`, `--float`, `--r-ctl`)가 `--m-fast` 동안 살짝 커지며 떠오르고(.96 → 1), 제목 아래에 놓으면 할 일이 `--fg-3` 12/16으로 따라와요.
  끌고 있는 행은 올렸을 때 모양(`--card-hover`)으로 남아요. 놓을 구역은 파일 끌어놓기와 같은 말로 `--accent` 12% 채움 + `--ff-ring`이고, 가장자리 구역은 칸의 왼쪽·오른쪽 1/4이고(위·아래는 없어요), 나누면 280px보다 좁아지거나 이미 두 칸이면 구역이 칸 전체(바꾸기)예요.
  구역은 처음 `--m-fast`로 나타나고, 커서를 따라 가장자리·가운데·다른 칸으로 옮길 때 보드의 자리 표시(`.bph`)처럼 `--m-fast` 동안 미끄러져요.
- 모니터링과 인앱(카카오톡 방, 댓글 스레드, DM)은 칸 안에서 1100px 미만의 한 단 모양이에요: 열린 방이 칸을 다 쓰고, `메일 쓰기`는 칸 안 오른쪽 아래(`--sp-4`)예요.
- 칸에 넣을 수 없는 행(`앱 관리`)은 끌기 시작부터 제목이 `--fg-3`, 아래 줄이 `칸에 넣을 수 없어요`, 커서는 금지 모양이고 구역을 그리지 않아요.
- 놓으면: 새 칸은 놓은 쪽에서 폭 0에서 자기 몸까지 `--m-base` 동안 자라며 옆 칸을 밀어내요(글은 늘어나지 않고 다시 줄을 바꿔요).
  가운데에 놓아 바꾼 칸은 제자리에서 `motionSwap`(투명도 .35 → 1, `--m-base`)이에요. 머리줄을 끌어 옮긴 칸은 원래 자리에서 미끄러져 와요.
  취소(Esc, 칸 밖에 놓기)하면 고스트가 `--m-base` 동안 집어 든 행으로 돌아가며 사라져요. 동작 줄이기에서는 모두 바로 바뀌어요.
- 경계선은 `--sp-4` 폭이고 평소에는 보이지 않다가 올리거나 끌 때 `--accent` 2px 선이 보여요. 두 번 누르면 반반이에요.
- 칸이 하나일 때와 1100px 미만은 분할이 없던 때와 같은 화면이에요.

## 진행 표시

**언제**: 끝날 시간이 있는 일의 정도(사용량, 업로드), 지금 일이 돌고 있음을 알릴 때.
**생김새**
- `.bar`: 높이 4px, 모서리 2px, 바탕 `--track`, 채움 `--accent`(주의 `.warn`, 한도 `.err`). 위 8px. 너비는 `width .3s`로만 바뀌어요.
- 정도를 알 수 없으면 막대 대신 `.dot.pri`와 "진행 중" 태그. 끝나면 같은 자리에서 결과(파일 칩)로 바뀌어요(`motionSwap`).
- 대화의 백그라운드 작업 줄은 맡긴 작업이 끝나면 그 줄이 같은 자리에서 완료·실패·중단됨으로 바뀌고, 결과 메시지가 있으면 누를 때 그 메시지로 가요. 새 줄을 더 붙이지 않아요. 상태는 이벤트가 아니라 게이트웨이가 알려요(`hub/workrows.ts`): 불러올 때는 `/api/history`의 `work`, 도는 동안은 스트림의 `work` 프레임. 그래서 게이트웨이가 꺼진 사이 끝난 작업도, 다른 세션의 작업도 다시 열면 맞게 보여요. 같은 작업을 가리키는 줄이 둘이면 둘 다 바뀌어요. 기록이 사라진 작업은 어떻게 끝났는지 모르니 회색 "끝남"이고, 같은 id를 새 작업이 이어받으면 옛 줄은 "중단됨"이에요.
- 이어진 백그라운드 작업은 카드 격자(`.cv-tasks`) 하나로 묶여요. 전체 폭은 늘 채팅 칸과 같고 한 줄에 3장까지, 남은 줄은 그 줄을 나눠 채워요(1장은 한 줄 전체, 2장은 나란히, 4장은 3 + 1, 5장은 3 + 2). 칸이 좁으면 한 줄에 2장, 더 좁으면 1장이고 창이 아니라 칸 폭으로 정해요(컨테이너 쿼리). 채팅 메시지가 끼면 격자가 끊기고, 접힌 도구 묶음은 끊지 않아요. 제목은 두 줄까지이고 내용만큼만 높아요(제목 아래 빈 자리 없음). 한 줄에 놓인 카드는 가장 높은 카드에 맞춰 같은 높이로 늘어나요. 결과 파일은 제목 아래 줄에 붙고 막대는 카드 아래 여백에 떠요.
- 숫자는 막대 옆 12px `--fg-3`, 바뀌면 `rollCount`(바뀐 자릿수만). 끝난 값은 그대로 두고 새 펄스를 주지 않아요.
**하지 말 것**
- 도는 스피너나 반복 움직임을 쓰지 마세요. 이유: 원칙 8, 원인 없는 움직임이에요.
- 막대 색을 장식으로 바꾸지 마세요. 이유: 색은 상태(정상·주의·한도) 하나만 뜻해요.
- 끝난 뒤 "완료"만 남기지 마세요. 이유: 원칙 7, 결과물이 있어야 끝난 거예요.

## 다른 컴퓨터에서 온 메시지

**언제**: 다른 게이트웨이가 이 대화에 남긴 메시지. 작업 넘김(`[peer handoff from ...`), `dotz_peer` send(`via`가 붙은 글), 넘긴 작업의 수신 확인(`✅ ...에서 넘긴 작업을 받아 이어서 해요`) 세 가지예요. 그 컴퓨터 페이지에서 형이 직접 보낸 메일·설정 대화의 글과 결정 답은 평소 말풍선이에요.

- 카드(`web/js/01-peer-msg.js`): 컴퓨터 아이콘, 컴퓨터 이름, 종류 태그(`작업 넘김` / `메시지` / `작업 받음`), 그 아래 형의 말. 코드 서식은 그대로이고, 인계 메모는 `인계 메모`를 한 번 눌러 펼쳐요. 긴 글은 말풍선처럼 6줄에서 접혀요.
- 영어 지시문은 보이지 않을 뿐 저장된 글과 에이전트가 받는 글은 그대로예요. 표시만 바꿔요.
- 대화 목록 미리보기, 알림 행, 인용은 같은 한 줄이에요: `맥미니에서 작업을 넘겼어요`, `맥미니에서 작업을 이어받았어요`. `dotz_peer` send는 이미 평문이라 글을 그대로 보여 줘요.
- 판별은 글의 맨 앞만 봐요. 대괄호로 시작하는 보통 메시지는 그대로예요.

## 인용 이동

**언제**: 메시지 위 인용이나 입력창 위 인용 줄을 눌렀을 때. 대화, 프로젝트, 다른 컴퓨터의 대화, 폰 모두 같아요.
**생김새**
- 원글이 그려져 있으면 부드럽게 스크롤하고, 저장돼 있거나 멀리 있으면 그 자리로 바로 가요. 강조는 알림 이동과 같은 `ntFlash`예요.
- 불러오는 동안 누른 인용에만 "찾는 중…"이 작게 떠요. 빠르면 나타나지 않아요.
- 원글 둘레 한 쪽(150건)만 한 번에 받아요(`GET /api/history?around=`). 지금 보던 쪽과 이어지지 않으면 그 사이에 "사이 메시지 불러오기" 줄이 남아요(`.msg-gap`).
- 원글이 없으면 토스트 하나로 알리고 화면은 그대로예요.
**하지 말 것**
- 원글까지 쪽을 차례로 넘기지 마세요. 이유: 화면이 깜빡이고 전체 기록이 메모리에 쌓여요.

## 화면 공유 (설정 섹션 · 앱바 알약 · 열기)

**언제**: 이 컴퓨터 화면을 다른 기기의 브라우저에서 볼 때. 맥에서 기능을 켠 컴퓨터에만 있어요. `/api/state`에 `desk`가 없으면 아래 모든 것이 없고 자리도 남지 않아요(원칙 13).
**생김새**
- 설정의 `연결` 목록 바로 아래에 `화면 공유` 섹션(`.sec` + `.list`) 하나예요. 행은 설정 행 규칙 그대로(`.li` + 오른쪽 `.li-end` 하나)이고 위에서부터 `이 컴퓨터 화면`(버튼), `화면 공유`(스위치 `.hs-sw`), `공개 주소`(스위치, 웹 접속이 Cloudflare일 때만)예요. 조작은 항상 되어서 조작 스위치가 없고, 보는 사람 목록 행도 없어요. 화면 공유가 꺼져 있으면 첫 행만 남고, `공개 주소`는 웹 접속이 Cloudflare일 때만 나와요.
- 앱바 알약 `.dsk-pill`은 `S.desk.viewers`가 있는 동안만 `연결 끊김` 칸(8번째 칸)에 떠요. 작은 상태 태그(`.tag.pri`, 파랑 = 진행 중)이고 한 명이면 기기 이름이나 사용자, 여럿이면 개수예요. 나타날 때 `motionIn`, 사라질 때 `motionOut`, 글이 바뀌면 `motionSwap`이고 처음 그릴 때는 움직이지 않아요. 누르면 설정으로 가요. 연결이 끊겨 `.conn`이 보일 때는 알약을 숨겨요.
- 여는 곳은 터미널과 같은 높이예요: 명령 팔레트의 `화면 공유 열기`, 컴포저의 `/screen`(게이트웨이로 보내지 않아요), 설정의 `이 컴퓨터 화면` 행 버튼(꺼져 있으면 `켜고 보기`, 켜면서 열어요), 컴퓨터 목록 시트의 컴퓨터별 `화면 보기` 버튼(`.pr-desk`, `.btn.tonal.inrow`). 다른 컴퓨터가 꺼져 있으면 토스트가 할 일 하나와 그 컴퓨터로 가는 동작을 줘요. 진짜 Chrome(`userAgentData.brands`에 `Google Chrome`)이면 답을 기다렸다가 새 탭을 열고, 그 밖의 브라우저는 누르는 순간 빈 탭을 열어 답이 오면 `/desk/`로 보내거나 닫아요.
- 누르면 화면이 바로 열려요. 다른 컴퓨터도 한 번 쓰는 표(`go`)를 받아 중간 페이지 없이 들어가고, 표 없는 링크만 `화면 열기` 페이지를 거쳐요.
- 화면은 voxl 페이지 안에서 `features/remote-desktop/viewer.js`가 맞춰요. 터치 기기는 빈틈 없이 채우고(가운데부터, 일부만 보여요) 두 손가락으로 줄이면 전체가 보여요. 마우스는 전체가 보여요. 한 손가락은 원격 포인터, 두 손가락은 내 화면의 확대와 이동이에요. 첫 터치나 클릭에 전체화면을 한 번 요청해요.
- 토스트는 한 줄 해요체예요: 막히면 이유, 보는 쪽 컴퓨터의 Chrome에서 열었으면 `<이름>의 크롬에서 열었어요`, 이 컴퓨터에서 열면 단축키 안내 한 줄이에요.
**하지 말 것**
- `navigator.keyboard`로 Chrome을 가리지 마세요. 이유: Aside를 포함한 모든 Chromium에 있어서 브라우저를 말해 주지 않아요.
- 알약이나 행을 `desk`가 없는 컴퓨터에 비워 두지 마세요. 이유: 원칙 13, 없는 요소의 자리는 남기지 않아요.
- 보는 사람이 없을 때 알약을 회색으로 남기지 마세요. 이유: 알약은 지금 바뀔 수 있는 값(보는 사람)이 있을 때만 있어요.
- 상태를 알리려고 주기적으로 물어보지 마세요. 이유: 알약은 이미 오는 상태 새로고침을 따라가요.

## 첫 설정 (/setup)

**언제**: 새로 설치한 뒤 처음 한 번. 설치 스크립트가 브라우저로 한 번만 쓰는 주소를 열어 줘요. 같은 컴퓨터에서만 열리고, 끝나면 `/setup`은 404예요. 자세한 흐름과 보안은 `docs/web-onboarding.md`예요.
**생김새**
- 앱의 부품을 그대로 써요(`.list`, `.li`, `.card`, `.btn`, `.tag`, `.dot`, `.bar`). 1280은 왼쪽에 단계 목록과 오른쪽에 한 단계, 390은 위에 `2/6`과 막대와 아래에 고정 버튼이에요. 주인공은 단계 제목 하나예요.
- 처음 화면은 이 컴퓨터를 한 번 훑어서 찾은 것을 행으로 보여 주고, 이미 준비된 것은 묻지 않고 넘어가요.
- `--no-open`, SSH, 화면 없는 컴퓨터에서는 설치 스크립트가 주소를 터미널에 찍고, 터미널 마법사(`bun setup.ts`)로 이어서 할 수 있어요.
**하지 말 것**
- `/setup`에 앱의 다른 화면을 섞지 마세요. 이유: 끝나기 전에는 게이트웨이가 온보딩 경로만 열어요.

## 화면 안내 (첫 설정 뒤 한 번 · 설정 > 앱 > 화면 안내 다시 보기)

**언제**: 첫 설정이 끝나고 앱이 처음 열렸을 때 한 번. 봤는지는 게이트웨이가 기억하고(`GET`/`POST /api/intro`) 브라우저를 바꿔도 다시 안 떠요. 터미널 마법사로 새로 설치한 경우도 같고, 원래 있던 설치는 스스로 뜨지 않아요.
**생김새**
- 진짜 메뉴 하나에 구멍을 낸 어두운 막과 그 옆의 카드(`.intro-spot`, `.intro-tip`) 하나예요. 순서는 홈, 채팅, 프로젝트, 모니터링, 설정, 단축키 여섯 곳이고 카드에는 `n/6`과 `.bar`, 제목, 설명, `건너뛰기` `이전` `다음`이 있어요. 마지막은 `시작하기`예요.
- 1024 이상에서는 메뉴의 오른쪽에 뜨고, 그보다 좁으면 탭바 바로 위에 떠요. 메뉴가 안 보이면 가운데에 떠요. 단축키 단계는 메뉴가 없어 가운데에 뜨고, 손가락 입력 기기에서는 이 단계가 빠져요. 앱 탭을 끈 사람은 앱 설명만 빠져요.
- 단축키 목록은 코드에서 읽어요: `⌘K`는 명령 버튼의 글자, `⌘/` `⌘.` `⌘\`는 `MOD_KEYS`(`web/js/04-state.js`), 탭 번호는 `navTabs()`예요. 맥은 `⌘`, 그 밖에는 `Ctrl+`예요.
- 키보드는 `Esc` 건너뛰기, `←` `→` 이동이고, 초점은 카드의 주 버튼에 가며 `Tab`은 카드 안에서만 돌아요. 끝나거나 건너뛰면 홈에 남고 이전 초점을 돌려줘요.
- 앱이 다 뜬 뒤에 시작하고 부팅을 막지 않아요. 같은 탭에서 한 번 봤다고 확인한 뒤에는 다시 묻지 않아요.
- 설정의 `앱` 목록에 `화면 안내 다시 보기` 행(`stRow`)이 있고, 누르면 같은 안내를 처음부터 열어요.
**하지 말 것**
- 단축키 목록을 글자로 옮겨 적지 마세요. 이유: 키가 바뀌면 안내만 어긋나요.
- 안내를 열 때 모델이나 `/api/state` 말고 다른 요청을 부팅 경로에 끼우지 마세요. 이유: 첫 화면이 느려져요.

## 검사할 수 있는 규칙

여백·정렬은 `hub/layout-measure.ts`가 데모 데이터로 주요 화면을 390·1280에서 재고(좁은 상자, 입력칸과 옆 버튼 높이, 동심 모서리, 왼쪽 시작선, 아이콘과 글자의 세로 중심, 같은 종류 행의 높이), `hub/layout-measure.test.ts`가 `hub/layout-baseline.json`과 대조해요. 값 눈금은 `web/DESIGN.md` Space scale이에요. 그 밖의 규칙은 나중에 웹 테스트가 렌더된 화면에서 재요. 숫자는 CSS px, 요소의 `getBoundingClientRect`와 `getComputedStyle` 기준이고 (정상 포인터, 라이트·다크 둘 다)예요. 기준에 걸리면 고치되, 의도한 예외는 명세에 이미 적힌 것만 허용해요.

| 이름 | 걸리는 조건 | 예외 |
|---|---|---|
| 글자 안쪽 여백 부족 (tight inset) | 글자 상자와 가까운 `.card`·`.li`·`.fs-card`·`.sheet`·`.snack` 가장자리가 가로 8px 미만 | 막대·구분선 |
| 뚱뚱한 행 (fat row) | 한 줄짜리 `.li`의 높이가 글자 줄 높이의 3배 초과(22px 글자면 66px 초과) | 설명(`.sup`)이 있는 행 |
| 닿음 (touching) | 이웃한 컨트롤·글자 상자 사이 간격이 0 초과 8px 미만 | `.chips` 4px, `.seg` 2px, 아이콘+글자 6px, 점+글자 6px |
| 위에 붙은 버튼 | `.btn` 위쪽과 바로 위 `.fi`·`.sel`·`.list`·구분선 사이가 8px 미만 | 같은 줄(`.btns`)의 옆 버튼 |
| 한쪽 몰림 (lopsided) | `.btn`·`.sel`의 좌우 안 여백 차이가 4px 초과, 또는 `flex-grow > 0`인데 내용 너비가 상자의 절반 미만 | `.fi`, 가로 전체 너비 허용 예외(폰 시트 맨 아래) |
| 버튼 크기 이탈 | 정상 포인터에서 `.btn`의 높이가 36·32·28px이 아님(터치는 보이는 상자가 같고 `min-height` 44까지만) | `.ib` 아이콘 버튼(28/36) |
| 채운 버튼 중복 | 한 카드·화면·대화창에 채운 `.btn`(배경이 `--accent` 또는 `--err`)이 둘 이상 | 서로 다른 카드 |
| 설정 행 컨트롤 자리 이탈 | `.li` 안의 `.btn`·`.sel`·`.hs-sw`가 `.li-end` 밖에 있음, 또는 `.li-end`에 누를 컨트롤이 둘 이상, 또는 `.li` 안 `.btn`이 기본(36px) 높이 | 입력칸을 `.tx` 안에 둔 입력 행, `.ib` 빼기 |
| 목록 아래 떠다니는 버튼 | `.list` 바로 다음 형제 `.btn`이거나 너비가 부모의 90% 이상인 `.btn` | 폰 시트 맨 아래 주 동작 |
