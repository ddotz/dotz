# web/ rules

Read before changing a screen: `docs/ui-principles.md` (principles), `web/DESIGN.md` (tokens), `docs/ui-spec.md` (screens).

- One pattern across screens: reuse the existing row, card or sheet; do not add a variant for one screen.
- Before adding a screen or feature, look for an existing screen with the same job and extend it.
- One lead per screen: one bold element, and only what needs attention now stands out.
- New elements match their neighbours (position, size, weight, colour); anchors never move; judge shots against unchanged rows (`web/DESIGN.md` 판단 기준, 목록 줄 구성).
- Spacing comes from tokens only (`web/DESIGN.md`); `hub/design-rules-web.test.ts` fails on literals.
- Copy is natural Korean, written the way a person would say it, with no AI-sounding phrases.
- Screen text is not written in the code: add the key to `web/i18n/ko/<area>.json` and `web/i18n/en/<area>.json` together and read it with `TX("key", vars)` (`web/js/00-i18n.js`; index.html uses `{{key}}`). English is short app copy, not a translation of the Korean. `bun hub/web-i18n-check.ts` fails on a new Hangul literal in web/ and on a key missing from either list.
- A screen change moves the tests that pin it: `grep -l '<selector, id or i18n key you touched>' hub/*-web.test.ts`, run every hit and update the ones your change moved. One red web test skips the whole release slot.
- Before done: side-by-side before/after shots at 390px and 1280px, compared item by item with the request.

## Structure rules

- Module contract: each area keeps one state owner object, the mutator functions that change it, a paint function, and named hook functions registered once per screen with `screenHooks(id, { route, enter, back, chain })` (`web/js/03-screens.js`; one function per key per id, a second registration throws). `route(tgt)` reads the address target into the owner, `enter(tgt)` draws and loads once the view shows, `back()` returns true when it closed something on the screen itself, `chain(hash)` gives the routes from 홈 when they follow state. Model file: `web/js/25-settings-devices.js` (`DEV` owner, `loadDevices`, `renderDevices`, the `dvOpen` row dialog, `screenHooks("devices", { enter: loadDevices })`).
- Owners: `hub/web-structure-owners.json` names the files that may write each shared object or cross-file `let`. Every other file calls the owner's functions: `monDirty()` (repaint 모니터링), `monSigReset`, `monSelSet` for `MON`; `rqTopSave`, `rqSheetSet`, `rqMarkClear` for `RQ`; `kkViewSet`, `kkRoomsAsk` for `KK`; `cmRoomsSig`, `cmHeadSig`, `cmChatSig` for `CM`; `dmReset` for `DM`; `mxRouteSet`, `mxBox`, `mxPick` for `MX`. Need a write the owner has no function for? Add a one-line mutator in the owner's file and call it.
- Empty, loading and failed places: `emptyNode(text, retry, { id, role, compact, more })` (`web/js/05-command-palette.js`) is the only builder; never hand-make a `.empty` card.
- Add a screen (a settings page here; other tabs differ only in the row and the parent):
  1. a data-only row in `SCREENS` (`web/js/03-screens.js`): `tab`, `sub: true` for a settings page, `up` only where 뒤로 never depends on state, `title: TX(key)`, `ic`, and `html: true` when step 3 adds its section to `web/index.html`;
  2. the title and screen text keys in `web/i18n/ko/<area>.json` and `web/i18n/en/<area>.json`;
  3. its section, `<section class="view" id="v-<id>" hidden><div id="<id>"></div></section>` in `web/index.html` next to its siblings (or, without `html`, a `SET_PAGE` entry in `web/js/22-settings-pages.js`, which then builds the box);
  4. the code in the area's file (or a new file plus its key in `hub/web-areas.json`): owner object, loader, paint with `emptyNode`, `screenHooks("<id>", { enter })`;
  5. a `go("<id>")` call from the parent screen (a settings page: one `stRow` in `settingsList`, `web/js/22-settings-pages.js`);
  6. an entry in `hub/ui-surfaces.json` (copy `screen-devices`: `id` `screen-<id>`, `kind` `subscreen` for a settings page, `sites` `go:<calling function>:<id>` and `view:<id>`, `open`, `ready`); `bun test hub/ui-surfaces.test.ts` names a missing or stale key;
  7. `hub/<id>-web.test.ts` that opens it and checks what it draws;
  8. `bun hub/screen-map.ts` rewrites `docs/ui-screens.md`;
  9. `DOTZ_GOLDEN_WRITE=1 bun test hub/web-golden-web.test.ts`, then check that the `hub/web-golden.json` diff touches only the new screen's entries and the parent's new row (a settings page: `button.li.tap` grows by one in the `screen-settings` entries).
- Add an overlay (`docs/ui-spec.md` 시트·대화창): use one of the shared parts and nothing else. `ask(title, text, ok, danger)` resolves true or false for a short confirm; `dialog({ title, body, actions, mid: true })` for one input or a short list; `fsOpen({ label, onClose })` for a long edit or read; `showMenu(anchor, items, { value, onPick })` for a menu; the side drawer for a list read beside the screen: `showSheet({ label, gone, opener })` returns the body to fill, `sheetHead` sets its head, `hideSheet()` closes it whatever it shows, and each content keeps a close of its own that leaves the others alone (`closeSheet` in `06-subagents.js`, `closeHSheet` in `28-harness-project.js`). Never call `el("dialog")`, `showModal()` or `ovOpen(` directly. The few kept exceptions are the `overlaySites` keys of `hub/web-structure-allow.json`, each with its reason under `reasons`; a new one needs a written reason there. Then: its text keys in both i18n lists; an entry in `hub/ui-surfaces.json` (copy `dlg-device`: `kind` `dialog`, `sites` `dialog:<function that calls dialog()>`); `bun hub/screen-map.ts`; `DOTZ_GOLDEN_WRITE=1 bun test hub/web-golden-web.test.ts` and a `hub/web-golden.json` diff that touches only what the overlay's opener adds to its screen (none when the button sits inside a new screen's entries already re-recorded).
- Before done, run the always-run set once each: `bun hub/screen-map.ts --check`, `bun test hub/web-golden-web.test.ts`, `hub/web-structure-web.test.ts`, `hub/screen-map.test.ts`, `hub/ui-surfaces.test.ts`, `hub/engineering-rules.test.ts`, `hub/design-rules-web.test.ts`, `hub/screen-hooks.test.ts`, `hub/back-stack-web.test.ts`, `hub/nav-tabs-web.test.ts`, and `bun hub/web-i18n-check.ts`.
- Ratchet: `hub/web-structure-web.test.ts` counts foreign state writes, `go()` branches, overlay sites, raw network calls, `current` assignments and empty-state bypasses against `hub/web-structure-allow.json`. Numbers only go down: lower one in the same commit that removes the violation, never raise one. Pre-push refuses a raised number.
- Lanes: `hub/web-areas.json` maps every `web/js` file to one area. A lane edits the files of its own area; touching another area means calling that owner's mutators or hooks, not its internals.
- Never add code to `web/js/30-monitoring.js` (near its ceiling); new monitoring routing goes in `web/js/30-monitoring-route.js`, and edits to `30-monitoring.js` stay line-neutral or shrink it.
- The map of every screen and what opens what is `docs/ui-screens.md`, drawn from the code by `bun hub/screen-map.ts`; never edit it by hand.
