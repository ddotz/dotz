# dotz 클릭 시제품

dotz 웹 앱의 화면과 움직임을 눌러 보며 결정하려고 만든 **디자인 시제품**이에요. **실제 제품과 연결되지 않았어요.** 데이터는 전부 `data.js`의 가짜 값이고, 보내기, 삭제, 설치 같은 동작은 화면 안에서만 흉내 내요. 새로고침하면 처음 상태로 돌아가요.

## 여는 법

- 파일로 바로: `site/prototype/index.html`을 브라우저로 열어요(서버 필요 없음).
- 서버로: 저장소 루트에서 `bunx serve site`를 돌리고 `/prototype/`을 열어요.

## 툴바

화면 맨 위 툴바에 두 가지와 목록 링크가 있어요.

- **테마**: 라이트 / 다크. `localStorage`의 `dz-proto-theme`에 저장돼요.
- **모션**: 켜기 / 끄기. `localStorage`의 `dz-proto-motion`에 저장돼요. 시스템의 "동작 줄이기"가 켜져 있으면 저장된 값과 상관없이 꺼져요.
- **화면 목록**: `#index`로 가요. 88개 화면이 묶음별로 나와 있어요.

## 화면 목록

모든 화면은 주소의 해시로 열려요(예: `index.html#chat/formats`). 전체 목록은 `#index`예요. 처음 보기 좋은 화면:

- `#home` 홈 상태 카드
- `#chat/formats` 봇이 쓰는 모든 출력 형식
- `#chat/approve` 보내기 승인
- `#mail` 메일 (삭제 → 실행 취소)
- `#notices` 알림: 종에서 여는 독립 화면 (필터 · 다 읽은 목록 · 빈 화면 · 긴 제목 · 반복은 `#notices/…`)
- `#settings` 설정
- `#queue` 대기함 시안 (앱을 가리지 않는 한 목록, 실패가 맨 위, 같은 이유의 실패는 한 줄. 상태별로 `#queue/ask` · `#queue/failed` · `#queue/sent` · `#queue/one` · `#queue/fails` · `#queue/empty`, 채팅의 한 줄은 `#queue/chat`, 1건 카드는 `#queue/chat/one`)
- `#onboard` 웹 온보딩 전체 화면 (단계는 `#onboard/harness` · `tools` · `bot` · `discord` · `web` · `review` · `done`, 값은 새로고침해도 남고 툴바의 "온보딩 처음부터"로 지워요. 닫힌 주소는 `#onboard/expired` · `#onboard/closed`)
- `#intro` 화면 안내 A안(시트), `#intro/spot` B안(진짜 메뉴를 가리키기)
- `#form` 카드 추가 새 폼 시안 (실시간 미리보기 · 썸네일 보기 · 더 보기, 찬 상태는 `#form/filled`, 연 상태는 `#form/more`, 설정에 입힌 모습은 `#form/settings`)
- `#answers` 채팅 답 모양 시안 (같은 글을 지금 모양과 제안 모양으로 나란히, 카드를 쓰지 않는 곳까지)
- `#mailbox` 메일함 시안 (메일함별 목록은 `#mailbox/b/orders` · `offer` · `school` · `pay` · `general`, 설정은 `#mailbox/set/score`, 펼친 모습은 `#mailbox/set/score/match` · `/tone`, 추가는 `#mailbox/new`, 한 메일함에 있는 대화는 `#mailbox/m/m6`)

## 문서

- `INVENTORY.md`: 실제 제품에 있는 기능과 출력 형식, 시제품 어디에 있는지(없는 것은 "없음")
- `MOTION.md`: 구현된 모션의 시간 · 곡선 · 움직이는 값, 비교하는 법

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 틀(툴바, 사이드바, 화면 영역)과 스크립트 불러오기 |
| `proto.css` | 디자인 토큰, 모션 토큰, 모든 스타일 |
| `proto.js` | 틀 그리기, 라우터, 검색 팔레트, 시트 · 토스트 · 팝오버, 모션 헬퍼, 답장 초안 카드 |
| `data.js` | 가짜 데이터(대화, 메일, 프로젝트, 알림 등) |
| `s-chat.js` | 채팅, 답 형식 모음, 보내기 승인, 브리핑, 작업 화면 |
| `s-notices.js` | 알림 화면: 묶음 3개, 필터, 읽음, 반복 접기, 결정 시트 |
| `s-work.js` | 홈, 프로젝트, 모니터링, 메일, 답장 확인, 앱, 컴퓨터 |
| `s-settings.js` | 설정 화면들 |
| `s-form.js` | 새 폼 시안: 카드 추가, 같은 입력칸을 입힌 설정 폼 |
| `s-onboard.js`, `onboard.css` | 웹 온보딩과 화면 안내 (설계는 `docs/web-onboarding.md`) |
| `s-queue.js` | 대기함 시안: 멈춘 답장 한 목록, 실패 묶음, 채팅의 한 줄 |
| `s-answers.js`, `answers.css` | 채팅 답 모양 시안: 마크다운 모양을 읽어 그려요 |
| `s-mailbox.js`, `mailbox.css` | 메일함 시안: 메일 앱 안의 계정과 메일함, 옮기기, 메일함 설정, 추가 (가짜 값은 `data.js`의 `D.mailAccounts`, `D.mailboxes`) |

## 메일함 시안과 실제 코드

시안에서 메일 앱은 하나이고, 그 안이 계정 > 메일함 순서예요. 지금 코드는 계정마다 메일 앱 인스턴스가 하나씩(`mail`, `mail-2`) 있어서, 시안의 계정 한 개가 인스턴스 한 개에 대응해요. 인스턴스 저장은 그대로 두고 화면에서 하나로 합치면 돼요.

화면은 `#mailbox`(모든 계정), `#mailbox/a/p`, `#mailbox/a/w`(한 계정), `#mailbox/n/general`(같은 이름 묶음), `#mailbox/new`(계정부터 고르는 추가), `#mailbox/new/w/copy`(설정 복사), `#mailbox/expired`(로그인이 풀린 계정), `#mailbox/solo`(계정이 하나일 때)예요.

| 계정 화면 | 지금 있는 것 | 새로 필요한 것 |
|---|---|---|
| 계정 하나 | `hub/integrations.ts`의 메일 인스턴스: `custom/apps.json`의 `label`이 계정 이름, `account`가 zele 계정(`--account`), `filter`가 그 인스턴스 몫. 메일의 `NewMail.account`와 `zeleAccounts()`도 있어요 | 없음. 인스턴스를 계정으로 읽으면 돼요 |
| 메일 앱 하나 | 인스턴스마다 모니터링의 앱 한 줄과 메일 화면 하나 | 인스턴스를 묶어 앱 한 줄과 화면 하나로 그리는 일. 계정이 하나면 지금과 똑같이 보여요 |
| 계정 칩과 모든 계정 | 노트북 칩(`.gw`)의 모양과 팝오버 | 칩 자체, 인스턴스 메일을 합친 목록, 줄의 계정 표시, 계정별 안 읽음과 답장 필요 점 |
| 이름이 같은 메일함 합치기 | 없음 | 이름으로 묶어 숫자를 더하는 보기. 저장은 계정별 그대로예요 |
| 메일함의 소속 | `draft_rules`는 이미 인스턴스별 설정이에요 | 메일함 저장을 인스턴스 아래에 두기. 계정마다 기본 메일함이 하나씩 생겨요 |
| 답장 보내는 주소 | 메일을 받은 인스턴스의 `account`로 보내요 | 없음. 메일함 설정에 그 주소를 보여 주기만 해요 |
| 메일함 추가의 계정 고르기, 설정 복사 | 없음 | 계정을 먼저 고르는 단계, 다른 인스턴스의 메일함 설정을 복사하는 일 |
| 옮기기 범위 | 없음 | 같은 인스턴스의 메일함만 보여 주기. 계정을 넘어가는 이동은 만들지 않아요 |
| 계정 추가 | 앱 인스턴스 추가와 zele 로그인 | 칩에서 그 흐름으로 들어가는 입구 |
| 로그인이 풀린 계정 | zele가 `not authenticated`를 돌려주는 것 | 그 상태를 계정별로 저장해 알리는 일, 다시 연결 흐름 |

아래 표는 메일함 한 개 안의 항목이에요. 메일함은 어느 계정 하나에 속해요.

| 화면 | 지금 있는 것 | 새로 필요한 것 |
|---|---|---|
| 분류 기준 | `hub/app-settings.ts`의 `draft_rules`(`DraftRule`: name, when, how, files, on)와 `features/reply-drafts/lib/rules.ts`의 `matchRule`. 켜진 규칙을 차례로 보고 처음 맞는 하나를 짧은 모델 호출로 골라요. "내용을 보고 판단"이 곧 `when`이에요 | 보낸 사람, 제목, 내용 칩: 모델 호출 전에 글자로 맞춰 보는 단계. 규칙은 초안만 정하므로, 맞은 메일함을 메일에 저장하는 곳 |
| 처리 방식 | 앱 전체 `auto_draft` 스위치와 규칙의 `on` | 메일함마다 네 가지 값 하나 |
| 말투 | `settings.ts`의 `ToneKey { app, room }`: `room`이 있으면 `tone/<app>/<room>.md`, 없으면 앱, 그다음 설치 전체 말투. 메신저 방이 쓰는 그대로 메일함 id를 `room`에 넣으면 돼요 | 메일 쪽에서 `room`을 넘기는 일. 고친 점은 말투 파일의 고침 항목(`HEADINGS.corrections`)을 보여 주면 돼요 |
| 기본 지시 | 앱 전체 `draft_default` 뒤에 규칙의 `how`가 붙어요 | 없음. 메일함의 `how`로 충분해요 |
| 첨부 폴더 | `attachFolders[인스턴스]` 경로 하나, 규칙의 `files` | 메일함마다 폴더 여러 곳 |
| 받는 사람별 인사, 금지 문구 | 없음 | 메일함별 저장과 초안 프롬프트 반영, 금지 문구 검사 |
| 알림 | 앱 인스턴스별 알림 설정 | 메일함별 값 |
| 옮기기와 기준 배우기, 묶음 제안, 대화 한 곳 유지 | 없음 | 대화 단위로 메일함을 기억하는 저장, 옮길 때 조건 추가, 앱이 묶음을 찾는 작업 |
| 기본 메일함 일반 | `matchRule`이 아무것도 고르지 못한 경우 | 그 결과를 일반 메일함으로 표시 |
