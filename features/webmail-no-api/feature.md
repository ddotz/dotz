API도 IMAP도 zele 지원도 없는 메일 사이트(사내 웹메일 등)를 오너의 Aside 브라우저 로그인으로 쓰는 기능이에요. 처음엔 꺼져 있고, 오너가 zele로 안 되는 메일을 쓰고 싶다고 할 때 켜요. zele로 되는 계정이면 zele가 먼저예요. 메일을 다른 컴퓨터가 맡는 설치(그런 개인 규칙)에서는 그 규칙을 따르고, 온보딩도 사전 확인에서 멈춰요.

켜기(한 명령, 다시 돌리면 멈춘 단계부터 이어서):
`bun <dotz>/features/webmail-no-api/bin/onboard.ts <site> --url <받은메일함 URL> --channel ch:<id> --label "<이름>"`
- `<site>`는 영문 소문자 이름(예: work). 받은메일함 URL만 물어보고, 메일 작업 채널이 없으면 먼저 평범한 이름(예: "회사 메일")으로 만들어 `--label`에도 같은 이름을 줘요.
- 자동으로 해요: 사전 확인 → Aside 백그라운드 탭에서 저장된 비밀번호로 로그인 → 받은메일함 호출 기록(메일 한 통도 자동으로 열어 봐요) → 어댑터 생성 → 실제 목록·읽기 시험(읽기 주소를 못 봤으면 후보를 시험해 찾아요) → 설정·홈 카드·사이드바 → 새 메일 감시와 로그인 유지 감시 등록 → 모니터링에 이 사이트만의 메일 앱(그 이름의 행, 자기 설정과 감시) 등록(다시 돌려도 하나만). 게이트웨이가 꺼져 있으면 그 단계에서 멈추니 켜진 뒤 같은 명령을 다시 돌려요. 진행은 메시지 하나가 계속 바뀌며 보여요.
- 종료 코드 3(오너 확인 필요): 출력된 질문 하나를 그대로 오너에게 한 번 묻고(비밀번호 저장, 2차 인증 승인을 한 번에), "됐어" 같은 답이 오면 같은 명령에 `--approve`를 붙여 다시 돌려요. 2차 인증은 이 승인 뒤에만 보내요.
- 종료 코드 1(실패): 출력된 이유를 그대로 알리고, 고쳐지면 같은 명령을 다시 돌려요. HTML만 쓰는 사이트처럼 호출 기록이 안 되는 경우 출력이 HAR 파일(`--har <파일>`)이나 IMAP/zele를 안내해요.
- 상태 보기: `onboard.ts <site> --status`.

쓰기:
- 읽기는 자유롭게: `bin/mail.ts <site> list | read <id> | search <말>`.
- 새 메일: 감시가 메일마다 게이트웨이에 올려요(`POST /api/mail`, 키 `<site>-<id>`). 게이트웨이가 스레드와 웹 대화(`mail:<site>-<id>`)를 만들고 그 메일 하나로 깨우니, 스레드는 따로 열지 말고 `read <id>`로 본문을 읽어 요약해요. 게이트웨이가 못 받은 메일만 예전처럼 `mail <id> from=...: 제목` 한 줄로 깨우고, 그때는 메일마다 작업 채널에 스레드를 하나씩 열어요(kind 보낸사람, name 제목). 한꺼번에 많이 오면 최근 10통만 따로이고 나머지는 `mail-backlog` 한 줄이에요.
- `reply-drafts` 기능이 켜져 있으면 답장은 그 공통 흐름(오너 말투 초안, `draft.ts send`가 이 사이트로 보내요)을 따라요. 아래는 그 기능을 쓰지 않을 때예요.
- 답장·전달: `mail.ts <site> draft <받는이> <제목> <본문>`으로 초안을 만들고, MODE.md의 발송 승인 블록(`hub/draft-approval.ts`, `<id>`=초안id, 대상 줄은 `> 받는이:`)으로 물어요. `결정 답: ... → 1) 보내기`가 오면 `mail.ts <site> approve` 뒤 `send <초안id>`, `2) 고치기 - ...`는 고쳐서 다시 물어요. 승인은 15분·한 번이고, 승인 없는 전송은 거부돼요.
- 첨부: 이 사이트로는 파일을 붙여 보낼 수 없어요. 파일을 보낸다고 쓴 답장이나 파일이 붙은 초안은 승인 카드 첨부 줄에 보낼 수 없다는 것과 빠진 파일이 보이고, 파일이 붙은 초안은 보내지 않아요. 파일을 자주 보내야 하면 그 사이트 전용 플러그인(다른 메일의 파일을 붙여 답장·전달하고 보내기 전에 첨부를 확인, `repliesWithFiles`; docs/custom-plugins.md)을 만들자고 제안해요.
- 이어서 할 일·첨부 파일 폴더는 설정으로 묻지 않아요. 오너가 대화에서 말하면 그 턴이 알려 주는 방법으로 이 메일 앱의 기억에 저장해요.
- 로그인이 풀리면 감시가 백그라운드 탭으로 한 번 복구해 보고, 안 되면 알리고(같은 끊김은 12시간에 한 번) 다시 연결될 때까지 이 메일 앱 행에 "연결 끊김 · 시각 · 다시 로그인 필요"로 보여요. 그때는 `onboard.ts <site>`를 다시 돌려 로그인 단계부터 이어가요.

최적화 기본값: 5분 간격, 조건부 요청(바뀐 게 없으면 304로 본문 없이), 사이트가 보낸 그대로의 최소 파라미터, 로그인 유지는 게이트웨이가 모델 없이(30분 확인, 6시간마다 탭 새로고침). 받은메일함이 그대로면 토큰을 쓰지 않아요.
