처음엔 꺼져 있고, 사용자가 요청해야 켜져요. 켜도 사용자가 고른 채널·글·사이트만 읽고, 고르지 않은 곳은 아무것도 읽지 않아요. 읽기는 스크립트(`bin/watch.ts`)가 하고 모델을 부르지 않아서, 새 댓글이 없으면 토큰이 들지 않아요. 댓글은 웹 모니터링 > 앱의 유튜브·인스타그램·웹사이트 댓글 항목에 글마다 대화로 보여요. 말투는 `~/.dotz/custom/reply-drafts/tone/<출처>.md`에서 배우고, 출처 설정과 받은 댓글은 `~/.dotz/custom/comments/`에 있어요.

- 초안은 사용자가 웹에서 초안을 부탁하거나 채팅에서 `이 댓글 답글 써줘`라고 할 때만 만들어요. 출처마다 따로 켜는 자동 초안(기본 꺼짐)을 켜면 새 댓글마다 초안을 만들고 승인 `[ask]`를 올려요. 모델은 댓글 줄기, 글 제목, 지난 답글 몇 개만 봐서 한 건에 입력 약 4.8천, 출력 약 160 토큰으로 측정됐어요(구독 모델 한 번 호출, 초안마다 `drafts.json`에 기록하고 `bin/comments.ts status`가 평균을 보여 줘요).
- 사용자가 `1) 보내기`를 고르기 전에는 아무것도 올리지 않아요. 같은 댓글에는 한 번만 올라가고, 상태는 보내는 중, 보냄, 실패(이유)로 남아요. 규칙으로 자동 보내기는 사용자가 출처마다 켰을 때만 되고, 그때도 같은 관문을 지나요.
- 댓글 한 건 초안: `bun {repo}/features/comments/bin/comments.ts draft <댓글 id>`가 `[ask]` 블록을 찍으면 그대로 올려요. 댓글 id는 `bin/comments.ts status`나 웹이 알려 줘요.
- `[ask]`에 대한 `결정 답: ... → 1) 보내기`: `bun {repo}/features/comments/bin/comments.ts send <id>`. `→ 2) 고치기 - <내용>`: `comments.ts revise <id> --change "<내용>"`(찍힌 `[ask]`를 그대로 올려요). `→ 3) 보내지 않기`: `comments.ts drop <id>`. `<id>`는 질문 끝 괄호의 초안 id예요. `send`가 거부하면 이유를 그대로 알리고 다시 시도하지 않아요.
- 여러 건을 한꺼번에(사용자가 "밀린 거 다 해", "28건 처리" 등): 건마다 `comments.ts draft <댓글 id>`로 초안을 만들고(카드를 손으로 쓰지 않아요. 질문 끝 괄호가 초안 id여야 게이트웨이가 보낼 수 있어요), 메일이 필요한 건은 바로 `mail-cli.ts compose ... --origin comment:<댓글 id>`(그 답글 카드에 붙어 한 장이 돼요)를 실행한 뒤, 찍힌 카드를 모두 한 번에 올리고 턴을 끝내요. 게이트웨이가 대화마다 한 장씩 보여 주며 `남은 N건`을 붙이고, 많으면 웹이 빠른 처리 화면을 열어요. 사용자가 고른 `1) 보내기`는 게이트웨이가 직접 순서대로 보내므로 그 답은 턴으로 오지 않아요. 턴으로 오는 건 `고치기`와 게이트웨이가 보낼 수 없는 카드뿐이에요(`결정 답 N건:` 한 메시지에 모여 와요). 실패는 게이트웨이가 `[fail]` 한 줄로 알려요.
- 끄기: `bun {repo}/features/comments/bin/onboard.ts off --app <youtube|instagram|site-이름>`. 읽고 있는 상태 확인: `onboard.ts status`, `comments.ts status`.
- 답글과 메일이 한 번에 필요할 때(댓글이 파일을 달라고 하고 주소를 적었거나, 사용자가 답글과 메일을 함께 말했을 때): 답글 초안을 만든 직후(`comments.ts draft <댓글 id>`가 찍은 초안 id) `bun {repo}/hub/mail-cli.ts compose --app <메일 앱> --to <주소> --subject <제목> [--attach <경로>]... [--from-library <키워드>] --with-comment <초안 id>`(본문은 stdin)를 실행해요. 출력은 받는이·제목·첨부·본문이 있는 메일 부분이 답글 아래에 붙은 `[ask]` 블록 하나예요. 고치지 말고 그대로 올려요. 사용자가 `1) 보내기`를 고르면 `comments.ts send <초안 id>` 한 번으로 답글을 올린 다음 메일을 보내요. 메일 초안 id로 `mail-cli.ts send`를 따로 부르면 거부돼요. 메일이 실패하면 답글은 올라간 채로 실패 이유를 알려 주니, 사용자에게 그대로 전하고 `mail-cli.ts ask --draft <메일 초안 id>`로 메일만 다시 물어봐요. `2) 고치기 - <내용>`은 내용이 답글이면 `comments.ts revise <초안 id> --change "<내용>"`, 메일이면 `--part mail`을 붙여요. 어느 쪽인지 모르면 사용자에게 한 번만 물어봐요. `3) 보내지 않기`는 `comments.ts drop <초안 id>`가 답글과 메일을 함께 버려요. 이 카드는 이어서 할 일 규칙을 깨우지 않아요. 메일이 나중에야 정해지면 아래 이어서 할 일 규칙이 그대로 맡아요. 외부 스크립트는 초안 API의 `extra`에 `{ "note": "...", "mail": { app, to, subject, body, attach?, fromLibrary? } }`를 담아 같은 카드를 만들어요(`docs/comments-api.md`).
- 답글과 메일 중 하나만: 카드에서 `답글만 보내기`·`메일만 보내기`를 골랐거나(카드가 그 선택지를 보여 줄 때) `1) 보내기`를 고른 뒤 사용자가 한쪽만 보내라고 했으면 `comments.ts send <초안 id> --only reply|mail`을 실행해요. `reply`는 답글만 올리고 메일 초안은 따로 남겨요(찍힌 `mail-cli.ts ask --draft <메일 id>`로 다시 물어요). `mail`은 메일만 보내고 답글 초안은 혼자 남아 찍힌 `[ask]`를 그대로 올려요. `어떻게 보낼지 직접 입력 - <글>`을 골랐으면 그 글대로 `send`(`--only`), `revise`, `drop` 중 하나를 실행해요. 한 번에 한 사람 몫만 처리해요.
- 메일 대조와 지난 답 참고(출처마다, 기본 꺼짐): `config.json`의 출처에 `"mailMatch": true`를 두면 초안을 만들 때 zele로 메일함을 읽기만 해서 댓글 단 사람이 메일을 보냈는지, 답장했는지를 카드의 `메일 대조:`·`근거:`·`초안 메모:` 줄로 보여 줘요. `"pastSeed": true`면 사용자가 예전에 비슷한 댓글에 단 답을 초안 모델에 같이 보여 주고, 모델이 답글을 비우면 가장 비슷한 지난 답을 초안으로 두고 `확인 필요:` 줄을 붙여요.
- 웹사이트 쪽지함: 사이트 설정에 `dm`(읽기·보내기 스크립트나 주소, `docs/comments-api.md`)을 두면 쪽지도 댓글처럼 `dm:<방>` 글로 들어오고 같은 초안·보내기 관문을 지나요. 보낸 뒤 그 방을 다시 읽어 내 답장이 마지막에 있을 때만 보냄으로 기록해요.
- 이어서 할 일: 답글을 올린 뒤(`1) 보내기`로 게시된 때만) 그 앱에 '이어서 할 일' 규칙이 있으면 게이트웨이가 `[followup:<앱>]` 턴을 한 번 보내요. 규칙·댓글 id가 담겨 있어요. 먼저 그 댓글이 규칙의 조건에 맞는지 `comments.ts`로 읽어 보고, 맞지 않으면 아무것도 만들지도 묻지도 않아요. 맞으면 `bun {repo}/hub/mail-cli.ts compose ... --origin comment:<댓글 id>`로 메일 초안(첨부 포함)을 만들어 [ask]로 올리고, 사용자가 `1) 보내기`를 고르면 `mail-cli.ts send --draft <코드>`로 보내요. 자세한 단계는 `features/reply-drafts/feature.md`예요.
