# 최악 데이터로 깨 보기 (worst-case)

화면이 예쁜 건 견본 데이터가 착해서일 수 있어요. 만든 뒤 최악 값을 넣어 일부러 깨 봐요.

## 켜는 법

- 개발 서버가 있으면 개발 전용 스위치를 둬요: `?data=worst` 주소 값이나 환경 변수로 데이터를 고르는 한 곳에서만 읽어요. 배포본에는 들어가지 않게 해요.
- 서버가 없으면 컴포넌트와 두 데이터를 한 HTML 파일에 담아요.
- 켠 채로 점검 명령을 390px과 1280px에서 돌리고 스크린샷을 봐요.

## 넣을 값

- **이름·제목**: 80자 넘는 이름, 띄어쓰기 없는 긴 한 덩어리, 한 글자, 빈 값.
- **이메일·주소·경로·해시**: 끊을 곳이 없는 긴 문자열.
- **개수**: 0개(빈 상태), 1개(복수형 "1 items"가 틀리지 않는지), 1000개 이상(느려지거나 끝없이 길어지지 않는지).
- **숫자·금액·날짜**: 아주 큰 수, 음수, 소수점이 긴 수, 0, 아직 없는 값.
- **섞인 글**: 한글과 영어와 이모지, 오른쪽에서 왼쪽으로 쓰는 글.
- **상태**: 오래 걸림, 실패, 일부만 도착.

## 깨짐의 모양

넘쳐서 옆 칸을 밀거나 화면 밖으로 나감, 잘려서 뜻을 잃음, 겹침, 높이가 들쭉날쭉, 숫자가 두 줄로 쪼개짐, 화면에 `NaN`·`undefined`·`null`이 그대로 보임 `[측정]`(마지막 것).

## 고치는 방향

- 이름·제목은 두 줄 안에서 줄이 바뀌게 하고, 보조 정보는 끝을 줄임표로 줄여요. 파일명과 이메일은 가운데를 줄여요.
- 여러 줄 미리보기는 `line-clamp: 2`로 카드 높이를 예측할 수 있게 해요.
- 숫자·금액·날짜는 줄이지 않고 자리를 줘요.
- 개수에 따라 글이 달라지면 0, 1, 여러 개를 따로 적어요.
