# 결과물 디자인 (output-design)

사람이 눈으로 볼 것을 만들 때 이 파일을 따라요: 홈 카드 `render.js`, 커스텀 앱 화면, HTML 페이지·보고서·슬라이드, 차트. 채팅 답과 글뿐인 보고는 대상이 아니에요. 켜는 스위치는 없어요.

## 먼저 정해요

1. 대상 프로젝트에 디자인 시스템이나 토큰이 있으면 그것이 먼저예요. 아래 원칙은 비어 있는 자리만 채워요.
2. dotz 안(홈 카드, 커스텀 앱)이면 dotz 클래스와 토큰만 써요(`docs/customization.md`의 render.js 단락, `web/css/01-tokens.css`). 색, 글자 크기, 고정 높이를 직접 적지 않아요.

## 다른 프로젝트에서 만들 때

1. 개발 서버를 띄우고 그 주소로 점검 명령을 돌려요: `bun <이 폴더>/bin/check.ts http://localhost:<포트>/<경로>`.
2. 개발 전용 스위치로 최악 데이터를 넣어 깨 봐요: 긴 이름, 끊을 곳 없는 이메일, 0·1·1000개 이상, 복수형, 아주 큰 수. 목록은 `worst-case.md`에 있어요.
3. 폰에서 쓰는 웹앱이면 `mobile.md`의 기준을 지켜요.
4. UI 일을 일꾼에게 맡기면 브리프에 이 SKILL.md 경로를 적어요. 일꾼은 기능 본문을 받지 못해요.

## 원칙 (규칙 · 확인)

`[측정]`은 아래 점검 명령이 재는 것이고, 나머지는 스크린샷을 눈으로 확인해요.

1. **처음 볼 것은 하나**: 그것만 가장 크고 굵게. 확인: 카드마다 가장 큰 글자 단계를 하나만 가져요. `[측정]`
2. **같은 말은 한 번**: 제목, 태그, 부제, 단추가 같은 뜻을 되풀이하지 않고, 점이나 아이콘이 보여 주는 상태는 글로 또 쓰지 않아요. 확인: 같은 뜻의 글 쌍이 없어요. `[측정]`
3. **한눈 상태는 점·아이콘·색**: 색만 쓰지 않고 모양이나 아이콘에 `aria-label`을 함께 둬요. 시각, 개수, 이름은 글이에요. 확인: "완료", "진행 중"만 적은 칸이 없어요. `[측정]`
4. **강조색은 누를 것, 선택된 것, 진행 중인 것에만**, 화면 넓이의 10% 이하. 확인: 날짜, 숫자, 아이콘이 강조색이 아니에요. `[측정]`
5. **색은 상태 색까지 6가지 이하.** `[측정]`
6. **카드는 할 일과 핵심 정보에만**: 카드 안에 카드를 넣지 않고, 아이콘 뒤에 옅은 색 상자를 깔지 않아요. `[측정]`
7. **테두리와 그림자 대신 여백과 회색 단계.** 그림자는 떠 있는 메뉴와 창에만 써요.
8. **없는 요소의 자리를 남기지 않아요.** 부제가 없으면 제목이 가운데에 서요. 빈 상태도 확인해요.
9. **글보다 구조**: 행, 칩, 숫자로 보여 줘요.
10. **견본 데이터는 실제처럼**: lorem ipsum, "항목 1" 금지.
11. **AI 티를 빼요**: 둥근 카드 한쪽의 색 줄, 색이 번지는 그림자, 그라데이션 글자, 아이콘 대신 이모지, 전부 주 단추. `[측정]` (줄, 그림자, 글자)
12. **글자**: 본문 12px 이상, 줄 간격 1.4 이상, 한 줄 약 75자(한글은 약 40자) 이하, 대비 4.5:1 이상(큰 글자 3:1). `[측정]`
13. **폰에서 누르는 곳은 44px 이상.** `[측정]`
14. **간격은 4px 격자.** 안쪽 모서리는 바깥 모서리에서 둘 사이 여백을 뺀 값이에요.
15. **움직임은 원인이 있을 때만**, `transform`과 `opacity`만, `prefers-reduced-motion`을 따라요. `transition: all`, `ease-in`, 300ms 넘는 길이(무한 반복 제외), `scale(0)` 시작, 너비·높이·위치·여백 움직임은 쓰지 않아요. `[측정]`
16. **폰 웹 기본과 샌 값**: 확대 잠금, 안전 영역, 상태 막대 색, `100vh`, 터치에 남는 hover, 16px 미만 입력칸(`mobile.md`), 화면에 그대로 찍힌 `NaN`·`undefined`·`null`·`[object Object]`·`Infinity`(`worst-case.md`). `[측정]`
17. **라이트와 다크, 390px과 1280px, 빈 상태와 찬 상태**를 모두 봐요. 가로로 넘치면 안 돼요. `[측정]` (390px)

## 순서

1. 첫눈에 보일 것 하나를 정해요.
2. 만들어요.
3. 스스로 열리는 것(앱 화면, HTML 파일, 보고서, 슬라이드, 차트)은 점검 명령을 돌려요: `bun <이 폴더>/bin/check.ts <주소 또는 파일.html> --shots <폴더>`. 홈 카드는 dotz 앱 안에서만 그려지고 주인 로그인이 있어야 열려서 이 명령이 혼자 열 수 없어요. 먼저 정해요 2의 dotz 클래스와 토큰 규칙을 따르고, 카드는 앱에서 봐요.
4. 스크린샷(390px, 1280px, 라이트, 다크)을 열어 눈으로 봐요.
5. 위반과 어색한 곳을 고치고 3부터 다시 해요.
6. 스스로 열리는 것은 점검이 0(깨끗)이고 스크린샷이 괜찮을 때만 끝났다고 말해요. 홈 카드는 규칙을 지켰고 앱에서 카드를 눈으로 봐서 괜찮을 때 끝났다고 말하되, 점검 명령으로는 재지 못했다고 함께 알려요.

## 점검 명령

- 390x844와 1280x800, 라이트와 다크로 열어 위반을 한 줄씩 보여 줘요: `[규칙] 화면 | 경로 | 잰 값`. 마지막 줄은 0~100 점수예요. `--json`은 기계가 읽는 형식이에요.
- 종료 코드: 0 깨끗함, 1 위반 있음, 3 막힘(이 기기에 WebView가 없거나 페이지가 안 열림). 막히면 끝났다고 하지 말고 이유를 그대로 알려요.
- 다크는 WebView에 전환 스위치가 없어서 `prefers-color-scheme` 규칙을 바꿔 끼워 재요. 출력의 참고 줄에 어떻게 됐는지 적혀요.
- 모델도 외부 네트워크도 쓰지 않아요. 주어진 주소만 열어요.

참고: 폰 웹앱과 최악 데이터 기준은 emilkowalski/skills(MIT)와 Meta Astryx의 글을 풀어 썼어요.
